# REST contract

`server.openapi.json` and `master.openapi.json` are the OpenAPI 2.0 documents the
Go nodes serve at `/apidocs.json`. They were generated by
`contracts/tools/openapi` and then checked against a running Go `gorse-server`
(port 8087) and `gorse-master` (port 8088): both are identical to the live
documents except for the order of `required` arrays, which go-restful-openapi
emits nondeterministically. `*.routes.md` flattens the same routes into tables.

- The server node serves 42 go-restful routes under `/api/` (`server/rest.go`).
- The master node serves those 42 plus 23 dashboard routes under `/api/dashboard/`
  on one go-restful WebService (`master/rest.go` `CreateWebService` then
  `server.RestServer.CreateWebService`), 65 in total.

The OpenAPI files describe paths, parameters and Go type names. The rules below
are behaviour the OpenAPI files do not capture; each was read from the cited code
and the bracketed ones were also observed on the running Go server.

## Response encoding

- Success bodies are JSON written by go-restful `WriteAsJson` with its default
  pretty printing: one-space indentation and a trailing newline is **not** added
  (`server/rest.go` `Ok`). [observed: `{\n "RowAffected": 1\n}`]
- Success responses carry `Content-Type: application/json` and
  `Access-Control-Allow-Origin: *` (set by `Ok` on every response, independent of
  the CORS filter). [observed]
- JSON field names are the Go struct field names unless a `json` tag says
  otherwise (`UserId`, `Labels`, `Comment`, `RowAffected`, ...). `time.Time`
  values are RFC 3339 with nanoseconds as Go's `encoding/json` writes them.
  Fields tagged `json:"-"` (for example `data.Item.UpdateAt`) are never sent.
- Every request routed through the go-restful WebService gets an
  `X-Request-ID` response header with a fresh UUIDv4 (`LogFilter`). [observed]
- Some read endpoints set `Last-Modified` from a cache value formatted with Go's
  `time.RFC1123` layout, which prints the zone as `UTC` rather than `GMT`
  (`SetLastModified`, keys in `../cache-keys.md`).

## Errors

- Handler errors are written by go-restful `WriteError`: status code plus the
  error message as the whole body, `Content-Type: text/plain; charset=utf-8`
  (set by Go's `net/http` content sniffing), and `Access-Control-Allow-Origin: *`.
  [observed: `404` `user nobody not found`; `400` `invalid character 'b' looking
  for beginning of object key string`]
- Unknown paths return go-restful's `404: Page Not Found`; a known path with the
  wrong method returns `405: Method Not Allowed` with an `Allow` header listing
  the route's methods. Neither carries `X-Request-ID`. [observed]
- Status codes used by handlers: 400 (`BadRequest`), 401 (`unauthorized`), 404
  (`PageNotFound`), 429 (`TooManyRequests`), 500 (`InternalServerError`), 503
  (readiness probe), plus `Error(response, status, err)` call sites.

## Authentication

- Server routes: if `server.api_key` is set, every route except
  `/api/health/*` requires header `X-API-Key` equal to it, else 401 `unauthorized`
  (`server/rest.go` `AuthFilter`).
- Master routes (`master/rest.go` `LoginFilter`, `checkLogin`): a request is
  logged in when `X-Api-Key` equals `master.admin_api_key`, or, with OIDC enabled,
  when the `id_token` cookie decodes to a cached token, or, with a dashboard user
  name or password configured, when the `session` cookie matches them, or when no
  dashboard credentials and no OIDC are configured at all. A logged-in request
  has its `X-API-Key` header replaced by `server.api_key` before the server
  filters run. Routes under `/api/dashboard` reject requests that are not logged
  in with 401 `unauthorized`; other `/api/` routes fall through to the server's
  own `AuthFilter`.
- Session cookies are encrypted with keys generated randomly at master start
  (`securecookie.GenerateRandomKey`), so they never survive a restart and never
  need to be readable by another implementation.

## CORS

A go-restful CORS container filter allows headers `Content-Type`, `Accept`,
`X-API-Key`, domains `master.http_cors_domains`, methods
`master.http_cors_methods`, no cookies (`server/rest.go` `StartHttpServer`). The
server node reads these values from the `master` section of the config it gets
from the master.

## Handlers outside the OpenAPI document

These are plain `net/http` handlers on the same listener, so they appear in no
OpenAPI file.

| Node | Path | Methods | Behaviour (source) |
|---|---|---|---|
| server, master | `/apidocs.json` | GET | The OpenAPI document (`restfulspec.NewOpenAPIService`) |
| server, master | `/apidocs/` | GET | Swagger UI (`swgui/v5emb`) |
| server, master | `/metrics` | GET | Prometheus exposition (`promhttp.Handler`) |
| server, master | `/debug/pprof/` and `/debug/pprof/{cmdline,profile,symbol,trace,allocs,block,goroutine,goroutineleak,heap,mutex,threadcreate}` | GET | Go pprof. A Rust node cannot produce Go profiles; see `PORTING_NOTES.md` |
| master | `/` | GET | Embedded dashboard single-page app; unknown files fall back to `/index.html`; redirects to `/login` (or the OIDC provider) when not logged in (`dashboard`) |
| master | `/login` | GET, POST | GET serves the SPA; POST form `user_name`, `password` sets the `session` cookie and redirects (`login`) |
| master | `/logout` | any | Clears `session`, redirects to `/login` |
| master | `/callback/oauth2` | GET | OIDC code exchange, sets `id_token` cookie |
| master | `/api/purge` | POST | Purges the data and cache stores; requires login, a configured dashboard password, and form value `check_list` naming every store to purge, comma-separated (`purge`) |
| master | `/api/bulk/users`, `/api/bulk/items`, `/api/bulk/feedback` | GET, POST | GET exports JSON Lines (`Content-Type: application/jsonl`, `Content-Disposition: attachment;filename=<kind>.jsonl`); POST imports a JSONL file uploaded as multipart form field `file` (`importExport*`) |
| master | `/api/dump` | GET | Binary dump, format in `../model-blobs.md` (`dump`) |
| master | `/api/restore` | POST | Restores a binary dump (`restore`) |
| master | `/api/chat/completions` | POST | OpenAI-compatible proxy used by the dashboard (`chatCompletions`) |
| worker | `/metrics`, `/api/health/live`, `/api/health/ready` | GET | Registered on Go's default mux by `worker/worker.go` `StartHttpServer`; no go-restful filters, so no `X-Request-ID` |

Errors from the raw master handlers are written by `master/rest.go` `writeError`
(plain text body, `Access-Control-Allow-Origin: *`) or by go-restful
`WriteErrorString`.
