# WP-2-10 notes: blob stores (`storage/blob`)

Ports: `storage/blob/blob.go`, `posix.go`, `s3.go`, `gcs.go`, `azure.go` and their
tests, all @ add21b5. Base: integration head ba01cae1 (merged at 7093baf).

Ids are provisional, as the brief asks: `D-WP210-*`, `Q-WP210-*`, `X-WP210-*`,
`O-WP210-*`. The integrator folds them into `PORTING.md` and `PORTING_NOTES.md`
and deletes this file.

## Decisions

- **D-WP210-1: async stores, ctx first (D-122).** `Store` and `BlobWriter` are
  `#[async_trait]`. Every method takes `ctx: &gocontext::Context` first and checks
  `ctx.err()` on entry and between units of work (each write, each list entry).
  No store holds a runtime and nothing calls `block_on`. No sync facade.
- **D-WP210-2: `done` is a oneshot.** `create` returns a
  `tokio::sync::oneshot::Receiver<()>`. Go closes `done`; the port sees a
  `RecvError` because the sender is dropped when the writer is closed or dropped.
- **D-WP210-3: POSIX IO through `tokio::fs`.** Each `tokio::fs` call runs on the
  blocking pool, which is the `spawn_blocking` the ruling asks for. The gRPC
  server's temp-file creation and rename call `spawn_blocking` directly.
- **D-WP210-4: cloud writes.** A writer buffers up to 5 MiB (the S3 minimum part
  size). Data up to that size goes up in one request on close. More starts a
  multipart upload with at most 4 parts in flight.
- **D-WP210-5: cancelled master uploads are aborted.** The master client runs each
  upload on its own task. A cancelled context aborts that task, so the stream is
  reset instead of ended. The server persists only a stream that ends normally,
  so a cancelled upload creates no blob (test `cancelled_upload_persists_nothing`).
- **D-WP210-6: NotFound.** `BlobError::kind()` maps POSIX `ErrorKind::NotFound`
  and object_store `NotFound` to `gorse_storage_core::errors::Error::NotFound`.
  gRPC missing-blob errors are not mapped (O-WP210-4).
- **D-WP210-7: crates.** `async-trait` 0.1.92 (dyn-compatible async methods, the
  crate-selection row), `tokio` 1.54.1 (the latest; this WP moved the crate from
  1.53.3 to 1.54.1 to match that row) with `fs`, `io-util` and `time`,
  `object_store` 0.14.2 (`aws`, `gcp`, `azure`), `tokio-stream` 0.1.19,
  `futures-util` 0.3.34, `bytes` 1.12.1, `url` 2.5.8, `percent-encoding` 2.3.2.
  Dev: `reqwest` (workspace) to seed the GCS emulator. `tokio-util` is not used.
- **D-WP210-8: gRPC list uses a background context.** The gRPC `ListBlobs` call
  carries no Go context. A dropped call is the only cancellation.

## Quirks kept

- **Q-WP210-1: one timestamp per chunk.** Go stamps every chunk with its own time,
  so the server rejects a second chunk of one upload (`inconsistent timestamp`).
  The port keeps this: the blob is not created and `Close` returns Ok. Test
  `quirk_second_chunk_is_rejected`. A temporary Go probe, since deleted, showed the
  same result.
- **Q-WP210-2: 4 MiB chunks exceed the gRPC limit.** A 4 MiB chunk plus its framing
  is larger than gRPC's default 4 MiB receive limit. The server refuses it
  (`received message larger than max (4194332 vs. 4194304)`) and no blob is created.
  A 3 MiB write is accepted. Test `quirk_full_size_chunk_exceeds_grpc_limit`.

## Deviations

- **X-WP210-1: S3 close returns the upload error.** Go's `S3.Create` runs
  `PutObject` on a goroutine behind an `io.Pipe`. Its error is logged and the
  pipe's `Close` returns nil. The port returns the upload error from `close` and
  logs it. The caller can see the failure. GCS already returns its writer's error
  in Go, and the port matches that.
- **X-WP210-2: list strips the prefix the same way.** Go's S3 `List` slices
  `Key[len(prefix):]` and drops one leading `/`. The port does the same with
  `strip_prefix`. The prefix is trimmed of slashes first, as the `Path` join is.
- **X-WP210-3: temp file removed on failure.** A failed master upload deletes its
  temp file. Go leaves an `upload-*` file behind (its `os.Rename` runs only after a
  full read).
- **X-WP210-4: write errors are returned.** POSIX and master writes return their
  I/O errors. Go's `io.Pipe` writes block or fail the copy goroutine instead.
- **X-WP210-5: EOF on the next read.** Go's minio reader returns `io.EOF` with the
  last bytes. The Rust readers report the end on the following read. The tests
  assert that second read returns 0.
- **X-WP210-6: missing env panics.** The cloud tests panic when a required variable
  is missing (`required_env`). Go's tests skip. A silent skip would look like a pass.
- **X-WP210-7: buckets are created out of band.** object_store has no
  `CreateBucket`, so `gorse-test` (and the Azure container) must exist before the
  cloud tests run. Go creates them in the test.
- **X-WP210-8: constructors return a Result.** `MasterStoreServer::new` returns
  `io::Result` where Go calls `log.Logger().Fatal`. The caller decides.
- **X-WP210-9: cancelled cloud multipart.** A cancelled write leaves an unfinished
  multipart upload, which the provider's lifecycle rule must clear. A cancelled
  POSIX write leaves the partial file, as Go does when its copy fails.
- **X-WP210-10: ctx on every method.** `Store` and `BlobWriter` take `ctx`, as D-122
  requires. Go's blob API has no context.

## Open

- **O-WP210-1: GCS write cannot run on fake-gcs-server.** The XML `PUT` to the
  emulator answers 400 `invalid uploadType` on 1.54.0, 1.56.1 and in the latest
  run. `test_gcs` is `#[ignore]`d with that reason. `test_gcs_read_list_remove`
  covers read, list and remove, with the seed uploaded through the JSON API. The
  write needs an emulator that serves the XML upload, or real GCS.
- **O-WP210-2: fake-gcs-server needs `-external-url` for path-style XML.** Without
  it, `GET /{bucket}?list-type=2` answers 404. This is an emulator setting, and the
  code is unchanged. Run it as `-scheme http -port 5051 -public-host 127.0.0.1:5051
  -external-url http://127.0.0.1:5051 -backend memory`.
- **O-WP210-3: live emulators.** RustFS runs as the `rustfs/rustfs:alpha` container
  on port 9000. Azurite runs from the npm `azurite` package on port 10000 with
  `--skipApiVersionCheck`. Buckets and the container are created before the test
  run. The environment variables are `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`,
  `S3_SECRET_ACCESS_KEY`, `AZURE_STORAGE_CONNECTION_STRING` and
  `GCS_EMULATOR_ENDPOINT`. The S3 keys are development-only and are not recorded here.
- **O-WP210-4: a missing blob over gRPC is `Unknown`.** Go's server returns the
  `os.Open` error as a plain error, which gRPC reports as code `Unknown`. The master
  client therefore cannot map it to `NotFound`. The integrator needs to choose: a
  status code on the server side, or matching the error text.
