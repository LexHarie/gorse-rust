## Deviations (provisional ids, checked against PORTING.md: none of these ids is in use yet)
- **D-WP44-1 Routing.** `/api/dashboard/*` goes to the dashboard routes; the other `/api/*` paths go to the server
  routes, behind the same login check. A trailing slash is dropped before matching, since go-restful matches with or
  without it. The one-off `/api/dashboard/user/{id}/feedback/` route is gone; the strip covers it.
- **D-WP44-2 Login filter.** The 401 for `/api/dashboard` without a login is the plain text `unauthorized`, with no CORS
  header. Interop: "dashboard route without login".
- **D-WP44-3 Unknown dashboard route.** 404 with the text `404: Page Not Found`, as go-restful writes it. Interop:
  "unknown dashboard route" and "unknown dashboard route without login".
- **D-WP44-4 Missing user.** The text is `user <id> not found`, Go's `fmt.Errorf("user %s %w")`. Interop: "missing user".
- **D-WP44-5 Dashboard files.** The bundle is embedded with rust-embed (debug-embed), excluding `README.md` and
  `MANIFEST.sha256`. `Last-Modified` is the process start time; Go's is its extraction time. Interop compares the
  presence of the header only. Conditional requests (`If-Modified-Since`) are not answered; the files are served whole.
- **D-WP44-6 Dump and export.** The whole output is built in memory before it is sent; Go streams. The bytes match.
- **D-WP44-7 Chat proxy.** The upstream reply is read whole, then sent as JSON or as an event stream; Go streams
  the upstream. Not run in interop: there is no upstream in the test.
- **D-WP44-8 Ranker prompt.** minijinja 3.0.4 replaces gonja. The interop case renders equal. A template that uses a
  gonja-only tag or filter is not checked.
- **D-WP44-9 Config POST body.** The body is decoded with `gorse_common::gojson` (encoding/json texts; `EOF` for a blank
  body). go-restful's content-type refusal and its gzip and deflate body handling are not reproduced: `read_entity`
  in gorse-server is `pub(crate)`.
- **D-WP44-10 Config map.** `porting/tools/config_map_gen.py` now matches rustfmt-wrapped `decode` calls. The
  generator had dropped those fields, so `config_map.rs` lacked some of them. The file is regenerated, not hand-edited.
- **D-WP44-11 Feedback expressions.** In the config JSON a feedback expression is its Go `String()`, for example
  `read>=3`.
- **D-WP44-12 Dump feedback records.** They omit `updated`, as Go's dump does (`master/rest.go` writes no `Updated`).
- **D-WP44-13 Ranker prompt keys.** The JSON keys are `query` and `documents`, as Go's struct tags give them.
- **D-WP44-14 External preview.** The script runs in `spawn_blocking`: the blocking HTTP client panics on an async
  worker.
- **D-WP44-15 OIDC.** `AuthCodeURL("")` sends no `state`, and the ID token check takes no nonce, as go-oidc's `Verify`
  takes none. The Rust port does the same. The missing CSRF `state` is Go's, carried over; flagged for the integrator.
- **D-WP44-16 Node type names.** The stats and tasks routes count `Server` and `Worker`, as Go does.
- **D-WP44-17 Clock values in interop.** A node's update time, a task's start and finish, the model fit times and the
  cache update times are masked when set; a zero time is compared as it is.
- **D-WP44-18 External null list and the empty task list (follow-up; provisional id, renumber at merge).** The
  external pull returned an empty vector for a script whose list is `null`, and Go answers `null`. `gorse-logics`
  `External::pull` now returns `Option<Vec<String>>` (`None` for `null`), and the master route answers `null` on
  `None`. This touches WP-3-7's crate, approved by the coordinator. The empty task list is pinned by the Go test
  `TestEmptyListMarshalsAsNull`, run by conformance `monitor_empty_list`.
