# WP-4-2 notes (server node), provisional ids

The earlier notes for this WP are folded into PORTING_NOTES.md (D-242, Q-265 to Q-267, X-212 to X-225). This file lists only what changed after that fold. The ids are provisional until the integrator folds them.

## Resolved

- **X-218 (deviation 7, exponent-form floats) is resolved.** The REST writer formats floats as `encoding/json` does: a whole float has no fraction (`1`, not `1.0`), and `e` notation outside `[1e-6, 1e21)` uses Go's exponent form (`1e+21`, `1.5e-7`). Pinned by `rest::tests::go_json_writes_floats_as_go_does`.
- **X-225 (the `HOSTNAME` fallback) is resolved.** `read_hostname` reads `/proc/sys/kernel/hostname`, drops one trailing newline as Go's `os.Hostname` does, and no longer reads `HOSTNAME`. Pinned by `server::tests::hostname_drops_one_trailing_newline`.
- **X-WP42-14 (JSON syntax, type and time error texts) is resolved.** The request decoder is now a port of `encoding/json`'s scanner and its typed walk (`rest/gojson.rs`, `rest/entity.rs`). Every non-EOF text matches Go 1.27.0:
  - syntax: `invalid character … looking for beginning of value`, `… looking for beginning of object key string`, `… after object key`, `… after object key:value pair`, `… after array element`, `… in literal true (expecting 'r')`, `… in numeric literal`, `… in string`, ``invalid escape sequence `\x` in string``, `unexpected EOF`;
  - depth: `exceeded max depth` past 10000 nested containers;
  - type: `json: cannot unmarshal V into Go struct field User.UserId of type string`, the `.0.Field` form for a list element, `Item.Categories.0` for an index, and `Go value of type` at the root; a float64 past range is `number 1e400`;
  - time: `parsing time "…" as "2006-01-02T15:04:05Z07:00": …`.
  - Checked by `rest::tests::decode::bodies_decode_as_go_decodes_them`, which runs 256 bodies from a probe that calls Go's `ReadEntity` (`porting/evidence/wp-4-2/go-readentity-probe`, with `make_fixture.py` building `go_decode.jsonl`), and by `nesting_past_the_limit_is_exceeded_max_depth`. The mixed test checks seven refused bodies over HTTP.
- **Content type (go-restful's gate) is resolved.** A body whose content type is neither JSON nor XML answers `[ServiceError:400] Unable to unmarshal content of type:<type>`, which is what go-restful's `ServiceError` text is. The gate runs before the body. The mixed test checks a request with no content type.
- **Truncated bodies** answer `unexpected EOF`, and a body of white space answers `EOF`, as before.

## New provisional items

- **X-WP42-16 (labels, known deviation).** Go keeps the numbers of an `any` value as `json.Number` text, and it does not refuse labels for their number range or their nesting. The port reads a label with serde, so a number past the `float64` range answers serde's `number out of range` text, and labels nested past serde's 128-level limit answer its recursion text. Go accepts both. Pinned by `labels_nested_past_serde_limit_are_refused_known_deviation`. A label number is stored as its `float64` value, so `1E+2` is stored and read back as `100`, which is Q-WP42-3 for numbers.
- **X-WP42-17 (XML bodies).** Go's XML decoder is not ported. An `application/xml` body with no `<` answers `EOF`, as Go does. One with a `<` answers `XML request bodies are not supported`, which is not Go's text.
- **X-WP42-18 (Content-Encoding).** go-restful inflates a `gzip` or `deflate` body. The port reads the raw bytes, so a compressed body answers the scanner's text for its first byte.
- **X-WP42-19 (quoting of non-ASCII characters).** Error texts quote a character as `strconv.QuoteRune` does. The port's printable test covers white space, format characters, private use and the noncharacters at the top of the planes, but not unassigned code points. An unassigned character quotes as itself where Go would escape it.
- **X-WP42-15 (host name read order, provisional).** Go tries `uname(2)` first and then `/proc/sys/kernel/hostname`. The port reads `/proc` only. On Linux both return the kernel's host name. The `uname` call would need a new crate (`rustix`) or unsafe code, which the workspace does not allow here.

## Mixed-cluster result

`conformance/tests/mixed_server.rs` sends 63 requests to the Go server and to the Rust server, over two WP-4-1 clusters with the same seed. The requests cover all 42 routes of `contracts/rest/server.routes.md`. Each reply must match in status, content type, CORS and request-id headers, and body text. **No request differs** at the new head. The test runs in about 18 seconds, and it fails rather than skips when Go is missing.

The seven requests added for this change are a type error and a syntax error on `POST /api/user`, a `POST /api/user` with no content type, a blank `PATCH /api/user/{user-id}`, a bad timestamp on `PATCH /api/item/{item-id}`, a `1e400` value on `POST /api/feedback`, and a wrong-type category on `POST /api/items`. At `10a5841` the test had 56 requests. An earlier report said 52, which was a miscount.

The one case the test does not cover is the neighbour lists past the end of the list (Q-WP42-1 below).

## Open questions

- **Q-WP42-1 (live check of `offset` past the end, open).** The item-to-item and user-to-user neighbour lists answer `null` past the end in Go. The check needs an item-to-item config, which `Cluster::new` edits cannot write yet, since it is an array of tables. The mixed test does not cover it.
- **Q-WP42-3 (float label text, open).** A label such as `2.50` is stored as `2.5`, and `1E+2` as `100`. Go keeps the text (X-221). Acceptable, or should the decoder keep the text? Related to X-WP42-16.

## Corrections to the earlier port

- **Master config decode (fixed in `8959c39`).** `sync_once` decoded the master's config with the snake_case mapstructure path. Go marshals the config with its Go field names and durations as nanoseconds, so the decode failed and the poll interval became zero. The loop then never slept and never opened a store. The loop now uses `Config::unmarshal_json`, as the Rust worker does. The `server_sync` test had snake_case input, which hid the bug, so it now sends the Go names.
- **Request decoding (replaced in this change).** The request bodies were decoded by serde, which gave serde's text for every error except the truncated body. They are now decoded by the port of `encoding/json` described above. Member names still match without regard to case, and a later member for a field still replaces an earlier one.
