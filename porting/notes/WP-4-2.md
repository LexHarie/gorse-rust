## Resolved

- **X-218 (deviation 7, exponent-form floats) is resolved.** The REST writer formats floats as `encoding/json` does: a whole float has no fraction (`1`, not `1.0`), and `e` notation outside `[1e-6, 1e21)` uses Go's exponent form (`1e+21`, `1.5e-7`). Pinned by `rest::tests::go_json_writes_floats_as_go_does`.
- **X-225 (the `HOSTNAME` fallback) is resolved.** `read_hostname` reads `/proc/sys/kernel/hostname`, drops one trailing newline as Go's `os.Hostname` does, and no longer reads `HOSTNAME`. Pinned by `server::tests::hostname_drops_one_trailing_newline`.
- **X-WP42-14 (JSON syntax, type and time error texts) is resolved.** The request decoder is a port of `encoding/json`'s scanner and its typed walk (`rest/gojson.rs`, `rest/entity.rs`). Every non-EOF text matches Go 1.27.0: syntax texts (`invalid character … looking for beginning of value`, `… after object key`, `… in literal true (expecting 'r')`, `… in string`, ``invalid escape sequence `\x` in string``, `unexpected EOF`), `exceeded max depth` past 10000 nested containers, type texts (`json: cannot unmarshal V into Go struct field User.UserId of type string`, the `.0.Field` form for a list element, `Item.Categories.0` for an index), and time texts (`parsing time "…" as "2006-01-02T15:04:05Z07:00": …`). Checked by the conformance test `go_decode`. The gorse-server fixture test `bodies_decode_as_go_decodes_them`, its fixture and the probe's stored oracle are removed (O-85).
- **Content type (go-restful's gate) is resolved.** A body whose content type is neither JSON nor XML answers `[ServiceError:400] Unable to unmarshal content of type:<type>`, which is go-restful's `ServiceError` text. The gate runs before the body is read. The mixed test checks a request with no content type.
- **Truncated bodies** answer `unexpected EOF`, and a body of white space answers `EOF`, as before.
- **X-240 (labels) is resolved.** A label number keeps its text, as Go's `json.Number` does, so a number past the `float64` range, or with a fraction or an exponent, is read as it was written. Labels nested to Go's 10000-level limit are decoded, and validated and written, without recursion, so serde's 128-level limit no longer applies to the decoder. Pinned by `rest::tests::decode::label_numbers_keep_their_text` and `labels_nested_past_the_serde_limit_are_decoded`, and by the `go_decode` corpus.
- **X-241 (XML bodies) is resolved.** The body is decoded by a port of `encoding/xml`'s strict `Decoder` (`rest/xml.rs`): the lazy tokenizer, entities, attributes, comments, CDATA, directives, processing instructions and the XML declaration check, the element stack with Go's end-element messages, and `Skip`. The struct mapping follows `unmarshal` for the Go types that take a body: strings, bools, float64, `[]string`, `time.Time` (parsed as `UnmarshalText` parses it), and `any` (skipped). Element names are matched by their Go field names, exactly. The name tables are generated from Go's own `encoding/xml` by `porting/evidence/wp-4-2/xml-name-table`, and `go_xmlname` checks the committed file against that output. The decoder stops reading when the root element closes, so bytes after it are not read, as in Go.
  - Checked by `go_decode`, which runs the probe on the named XML bodies (every error class above, the entity and CDATA forms, nesting to 5000 levels, and the unclosed forms) and on every truncation and corruption of one sample per route. The check was made live: changing one entity in the decoder fails exactly the row that uses it.
- **X-242 (Content-Encoding) is resolved.** `rest/inflate.rs` inflates a `gzip` or `deflate` body as go-restful does before it checks the content type: a `deflate` body with a bad zlib header fails at once, and a `gzip` body is read to its end, with multistream members, header flags and CRC checks. The error texts are Go's (`flate: corrupt input before offset N`, `gzip: invalid header`, `gzip: invalid checksum`, `zlib: invalid header`, `zlib: invalid checksum`), and the offsets are relative to the start of the deflate stream. Checked by `go_decode` on the gzip and zlib streams at levels 0, 1, 6 and 9, gzip members with each header flag, two members, every truncation of a stream, and every single-byte corruption at three masks.
- **X-243 (quoting of non-ASCII characters) is resolved.** `rest/printable.rs` holds Go 1.27.0's `unicode.IsPrint` as ranges (Unicode 17.0.0), generated by `porting/evidence/wp-4-2/printable-table`. `go_printable` checks the committed file against Go's output, so every code point quotes as Go quotes it, unassigned ones included.

## Provisional and open items

- **X-WP42-15 (host name read order, provisional).** Go tries `uname(2)` first and then `/proc/sys/kernel/hostname`. The port reads `/proc` only. On Linux both return the kernel's host name. The `uname` call would need a new crate (`rustix`) or unsafe code, which the workspace does not allow here.
- **X-WP42-20 (deep labels in storage) is open, per D-268.** The JSON paths (SQL and proxy) are done: the label walks are iterative, and Go's 10,000-level limit holds with Go's text, `exceeded max depth`. The MongoDB paths were still overflowing in the `bson` crate when the integrator ran the live test, so `99defa2` writes and reads label BSON without a `Bson` tree. The live test `mixed_mongo_deep_labels_match_go_server` has not run in this container (no Docker daemon). It is the integrator's to run, and X-244 stays open until it passes. Details: the section-8 report at `/mnt/project-files/reports/wp-4-2/section-8.md`.
- **Q-WP42-1 (live check of `offset` past the end, open).** The item-to-item and user-to-user neighbour lists answer `null` past the end in Go. The check needs an item-to-item config, which `Cluster::new` edits cannot write yet, since it is an array of tables. The mixed test does not cover it.
- **Q-WP42-3 (label numbers in storage, open).** The decoder keeps the text of a label number (X-240). Go's storage does not keep it either: the mixed test's `item-num2` case (labels `2.50` and `1E+2`) reads back as `[2.5, 100]` from both clusters. Whether the text should survive storage is for the integrator to decide.

## Corrections to the earlier port

- **Master config decode (fixed in `8959c39`).** `sync_once` decoded the master's config with the snake_case mapstructure path. Go marshals the config with its Go field names and durations as nanoseconds, so the decode failed and the poll interval became zero. The loop then never slept and never opened a store. The loop now uses `Config::unmarshal_json`, as the Rust worker does. The `server_sync` test had snake_case input, which hid the bug, so it now sends the Go names.
- **Request decoding (replaced in `e58e4ff`).** The request bodies were decoded by serde, which gave serde's text for every error except the truncated body. They are decoded by the port of `encoding/json` described above. Member names still match without regard to case, and a later member for a field still replaces an earlier one.
