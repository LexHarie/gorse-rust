# WP-4-2 notes (server node), provisional ids

The earlier notes for this WP are folded into PORTING_NOTES.md (D-242, Q-265 to Q-267, X-212 to X-225). This file lists only what changed after that fold. The ids are provisional until the integrator folds them.

## Resolved

- **X-218 (deviation 7, exponent-form floats) is resolved.** The REST writer formats floats as `encoding/json` does: a whole float has no fraction (`1`, not `1.0`), and `e` notation outside `[1e-6, 1e21)` uses Go's exponent form (`1e+21`, `1.5e-7`). The texts were checked with a Go probe, and they are pinned by `rest::tests::go_json_writes_floats_as_go_does`. Before the change, a score or feedback value was equal but its text differed, and the mixed test compares text.
- **X-225 (the `HOSTNAME` fallback) is resolved.** `read_hostname` reads `/proc/sys/kernel/hostname`, drops one trailing newline as Go's `os.Hostname` does, and no longer reads `HOSTNAME`. Pinned by `server::tests::hostname_drops_one_trailing_newline`.
- **Malformed bodies that end too soon** answer `unexpected EOF`, as Go's decoder does. Pinned by `rest::tests::a_body_that_ends_too_soon_is_unexpected_eof`.

## New provisional items

- **X-WP42-14 (syntax and type error texts, open).** Only the truncated-body case matches Go. Other JSON errors keep serde's text. Go's are `invalid character 'x' after object key`, and for a type mismatch `json: cannot unmarshal number into Go struct field User.UserId of type string`. The coordinator's ruling says error texts match Go exactly, so this is a gap. The mixed test covers only the truncated body, and it passes because that case matches. Closing the gap needs a Go-compatible JSON error layer, which the integrator should decide on.
- **X-WP42-15 (host name read order, provisional).** Go tries `uname(2)` first and then `/proc/sys/kernel/hostname`. The port reads `/proc` only. On Linux both return the kernel's host name, so the result is the same. The `uname` call would need a new crate (`rustix`) or unsafe code, which the workspace does not allow here.

## Mixed-cluster result

`conformance/tests/mixed_server.rs` sends 52 requests to the Go server and to the Rust server, over two WP-4-1 clusters with the same seed. The requests cover all 42 routes of `contracts/rest/server.routes.md`. Each reply must match in status, content type, CORS and request-id headers, and body text. **No route differs** at head `5210131`. The test runs in about 16 seconds with Go and the in-process SQLite and xvec stores, and it fails rather than skips when Go is missing.

The one case it does not cover is the neighbour lists past the end of the list (Q-WP42-1 below).

## Open questions

- **Q-WP42-1 (live check of `offset` past the end, open).** The item-to-item and user-to-user neighbour lists answer `null` past the end in Go. The check needs an item-to-item config, which `Cluster::new` edits cannot write yet, since it is an array of tables. The mixed test does not cover it.
- **Q-WP42-3 (float label text, open).** A label such as `2.50` is stored as `2.5`. Go keeps the text (X-221). Acceptable, or should the decoder keep the text?

## Corrections to the earlier port

- **Master config decode (fixed in `8959c39`).** `sync_once` decoded the master's config with the snake_case mapstructure path. Go marshals the config with its Go field names and durations as nanoseconds, so the decode failed and the poll interval became zero. The loop then never slept and never opened a store. The loop now uses `Config::unmarshal_json`, as the Rust worker does. The `server_sync` test had snake_case input, which hid the bug, so it now sends the Go names.
