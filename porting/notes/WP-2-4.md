## Decisions

- **D-WP24-1 The `Database` trait is `async` through `async-trait` (0.1.92,
  MIT/Apache-2.0, already in Cargo.lock).** Go's interface is used as a value
  (`Open` returns it), so the trait must be dyn-compatible; native `async fn`
  in traits is not. Storage WPs 2-1 and 2-8 face the same choice; this is the
  pattern to follow. Adding `async-trait` to `porting/crate-selection.md` is the
  integrator's call.
- **D-WP24-2 tokio is 1.54.1, not the 1.53.3 in the crate-selection table.**
  Ritchie's rule is the latest stable release, and 1.54.1 was published on
  2026-10-21. Tokio is a dev-dependency of `gorse-storage` for `#[tokio::test]`
  until a backend needs it in the library.
- **D-WP24-3 Context is the `gocontext` handle, passed by reference.** Go's
  `ctx context.Context` is the first parameter of each method. Deadlines do not
  exist in `gocontext`, so the suite's `WithTimeout` test uses a context that a
  timer thread cancels (see X-WP24-2).
- **D-WP24-4 `Registry` replaces Go's package-level map.** Go registers
  creators in `init`. Rust has no `init` for this, so the node builds a
  `Registry` and registers the backends it was compiled with.
- **D-WP24-5 `Error` carries Go's `errors.Is` as `Error::kind()`.** Sentinels
  are `gorse_storage_core::errors::Error`. `DocumentCondition` is Go's
  `fmt.Errorf("document condition: %w", ...)`. `Backend` is an
  `Arc<dyn Error>`, so `Error` stays `Clone` for `ReturnValue`, which hands its
  error out on every read, as Go's `ReturnValue` does.
- **D-WP24-6 `ScorePatch` fields are `Option`.** Go's nil `Categories` (no
  change) is `None`, and an empty non-nil slice (clear) is `Some(vec![])`.

## Deviations (X)

- **X-WP24-1 Strings are `String`, not bytes.** D-56 treats Go strings as bytes
  where they can hold any byte. Here every backend but Redis stores text as
  UTF-8, and Go's JSON and BSON encoders cannot store other bytes, so a
  `String` API matches every reachable input. A Redis value that is not UTF-8
  will be an error in WP-2-5 where Go returns its bytes; WP-2-5 must log that.
- **X-WP24-2 A test deadline is a cancel.** `gocontext` has no deadlines. The
  suite's `TestScanScores` timeout case cancels a context from a timer thread
  after 1 ms and accepts `Canceled` (Go accepts `DeadlineExceeded`). The
  backends must check `ctx.err()` between documents for the case to hold.
- **X-WP24-3 `Integer` returns only an error.** Go's `ReturnValue.Integer`
  returns the parsed number next to a range error. Every Gorse caller ignores
  the number on error, so `integer()` returns `Err` alone.

## Quirks (Q)

- **Q-WP24-1 `sort.Slice` is not stable.** Score documents with equal scores
  come out in pdqsort's order, not input order. `gosort.rs` reproduces that
  order. The two golden tests (40 and 200 items, with many ties) were generated
  with Go 1.27.0 by `sort.Slice` on the same inputs and match exactly.
- **Q-WP24-2 `Open` chooses among matching prefixes by map order in Go.** The
  port takes the longest matching prefix. Two creators with the same prefix
  replace each other, as `Register` does in Go.
- **Q-WP24-3 `Time` values are written and read as Go does.** The writer is
  `Time::string()` (with the `m=+` suffix for times from `now()`, Q-1). The
  golden strings in `cache/mod.rs` tests come from Go 1.27.0's `Time.String()`:
  `2026-01-02 03:04:05.678901 +0000 UTC`, `2023-01-01 00:00:00.0000005 +0000
  UTC`, and the `CEST` case, which reads back as UTC.

## Open (O)

- **O-WP24-1 The shared suite has not run against a backend.** No backend
  exists in this WP, and the acceptance command is `cache::no_database`. WP-2-5,
  2-6 and 2-7 must call `cache::database_test::run` with their store. Until
  then the suite is compiled and clippy-checked only.
- **O-WP24-2 Benchmarks are not ported.** `benchmark`, `benchmarkAddDocuments`,
  `benchmarkSearchDocuments`, `benchmarkUpdateDocuments`, the prime table and
  `BENCHMARK_DATA_SIZE` are not run by `go test`. Phase 5 performance work is
  the place for them.
