## Replay against Go

`contracts/tools/modelreplay -mode ctr` writes
`crates/gorse-model/testdata/ctr/afm_replay.json` (34.5 KB). It holds the
synthetic dataset (8 users, 10 items, 3 user labels, 4 item labels, 3 context
labels, 2 FP16 item embeddings of dimensions 4 and 3, 96 train and 32 test
samples), the hyper-parameters, the classification score after each of 5
epochs, and the 13 parameter tensors (241 values) after epoch 5.

Go fits each epoch count in a fresh child process with `GODEBUG=randautoseed=0`.
`ctr::replay::afm_replays_the_golden_fit` fits the same counts in Rust with
`set_init_seed(1)`.

- Largest difference from Go: **0** (exact) across every epoch score and every
  parameter value, against the tolerance of 1e-5 (D-195).
- Mutation check: adding 1e-4 to one golden parameter makes the test fail with
  `difference 9.998679e-5`. The golden was restored byte for byte.
- The generator reproduces the file byte for byte on a second run.
- `conformance/tests/ctr_replay.rs`, `ctr_oracle_matches_golden`, runs the
  generator again with `GODEBUG=randautoseed=0` and requires the output to equal
  the committed golden byte for byte. It fails when Go is not on PATH. Changing
  one golden value by 1e-6 makes it fail at line 2122.

Replay settings: BatchSize 16, NFactors 4, NEpochs 5, Lr 0.05, Reg 0.0002,
InitMean 0, InitStdDev 0.01, Adam, AutoScale true.

## Decisions

- D-WP32-1: The FM layers (linear, embedding lookup, attention) are built in
  `ctr::fm` with a per-model `Rand`, drawing in the order Go's `nn` layers
  draw. The `nn` global RNG is `pub(crate)` and not seedable, so the layers
  cannot come from it. The merged `nn` module is unchanged.
- D-WP32-2: Go's `Fit` returns only its last score, so per-epoch scores come
  from one child process per epoch count (`modelreplay`).
- D-WP32-3: Go's FM initial weights come from the process-wide `math/rand`.
  Go seeds that randomly unless `GODEBUG=randautoseed=0`, in which case it is
  seeded with 1. Rust keeps a random default seed, matching Go's default, and
  the replay sets `set_init_seed(1)`. See Q-WP32-1.
- D-WP32-4: `AutoScaler` uses a port of Go's `math.Log1p`, not libm, so that
  the float32 results agree.
- D-WP32-5: A context label id is absolute in the unified index and a user or
  item label id is local to its label names, as Go's `Dataset.Get` treats them.

## Quirks

- Q-WP32-1: Go's FM weight initialisation is random across runs unless the
  process sets `GODEBUG=randautoseed=0`. An unseeded Go fit therefore cannot
  be replayed. The Rust default matches that random behaviour.
- Q-WP32-2: `FactorizationMachines::predict` and `internal_predict` panic on
  the AFM. Go's `Predict` and `InternalPredict` panic with the same messages
  ("unsupported for deep learning models"), and the port keeps the panics.
- Q-WP32-3: Go's early stopping compares against `lo.MaxBy`, which keeps the
  first strictly greatest score. The port does the same.

## Deviations

- X-WP32-1: `Afm::parameters` is `pub(crate)` so the replay test can read the
  parameters. No behaviour change.
- X-WP32-2: The golden dataset has no timestamps. The FM fit never reads them,
  and `split_by_user_time` is covered by the `data` tests. The brief listed
  timestamps for the replay dataset; they are left out on purpose.
- X-WP32-3: The golden stores the train and test sets as explicit tables, not
  as one set split with `Split`. The split is covered by its own test.
- X-WP32-4: `set_params_reads_the_hyper_parameters_with_go_defaults` is an
  addition; Go has no such test.
- X-WP32-5: `evaluator_test.go` was missed in the first pass. Its three tests
  were ported before the report, against the same implementation.
