# WP-2-1 notes (data store core)

Provisional ids only. The integrator folds these into PORTING.md and PORTING_NOTES.md at merge and deletes this file.

## Decisions

- **D-WP21-1 The data `Database` trait is `#[async_trait]`, ctx first (D-122).** Methods that Go gives a `ctx` take `&Context` first. Lifecycle methods Go gives no `ctx` (`Close`, `Ping`, `Init`, `Reconcile`, `Optimize`, `Purge`) take none.
- **D-WP21-2 Go's chan pairs are one `BoxStream<'a, Result<Vec<T>, Error>>`.** `GetUserStream`, `GetItemStream` and `GetFeedbackStream` return a stream of batches. An error is the last item, which matches the order Go's consumers see on the two channels. The stream is borrowed from `&self` and `&Context`, and dropping it stops the scan.
- **D-WP21-3 Go's `int` counts are `i64`** (`n`, `batch_size`, the delete count, the counts), as the cache core uses `i64` for Go `int`. Go's `int` can be negative, and the backends must see the same value.
- **D-WP21-4 The registry is the cache core's.** `Creator` is a sync `fn` that returns `Box<dyn Database>`, and `Registry::open` takes the longest matching prefix. Go's `Open` picks among matching prefixes in map order, which is random, so the longest is the only deterministic choice that matches every path a prefix can match unambiguously.
- **D-WP21-5 `ScanOption` is a newtype over `Box<dyn Fn(&mut ScanOptions) + Send + Sync>`**, like storage-core's `Opt`. Each `with_*` function is a Go `With*` function.

## Deviations

- **X-WP21-1 Go's `NewScanOptions` skips nil options.** A `ScanOption` cannot be nil in Rust, so there is nothing to skip. Behaviour is the same for every value that can be built.
- **X-WP21-2 The shared suite's faker labels are fixed strings.** Go's `faker` colour and genre names are replaced with fixed strings. The cases only check that a label round-trips, so the values do not matter.
- **X-WP21-3 Go's `[]string` and `[]any` labels are one `Labels::Array`.** Go's conversions to `[]any` in the suite (`feedback[0].Labels = []any{"positive"}`, `[]any{"a", "b", "c"}`) are kept as the same value. The distinction is erased by `Labels`, which is the decision of D-117.
- **X-WP21-4 The suite's type switches are a `Backend` trait.** Go's `suite.Database.(*SQLDatabase)` and `*MongoDB` checks become `Backend::analyze_tables` (Postgres runs `ANALYZE`) and `Backend::time_stamps` (Postgres rounds to a microsecond, SQLite is exact, MongoDB truncates to a millisecond, others skip). TestTimezone skips for `TimeStamps::Unknown`, as Go's `Skipf` does.
- **X-WP21-5 Go's `TestSortFeedbacks` and `TestValidateLabels` are in `types.rs`.** WP-1-17 ported them, so the suite file does not repeat them.
- **X-WP21-6 Go's `time.Sleep(time.Millisecond)` is `std::thread::sleep`** in the suite. The suite runs on the test's own thread.

## Open

- **O-WP21-1 The suite is compiled and not run.** `data/database_test.rs` is called by no test in this crate. WP-2-2 (SQL) and WP-2-3 (MongoDB) run it against their stores. The acceptance command of this WP, `cargo test -p gorse-storage data::no_database`, runs only the NoDatabase case.
- **O-WP21-2 The cache core (WP-2-4, 559002c) is not merged.** This branch adds `async-trait`, `futures-core`, `futures-util` to the workspace dependencies, and `tokio` (dev-dependency, `macros` and `rt`) to `gorse-storage`. The cache core adds `async-trait` and its `tokio` dev-dependency too. The integrator resolves the `Cargo.toml` and `Cargo.lock` lines at merge.
- **O-WP21-3 Crate-selection rows.** `porting/crate-selection.md` needs rows for `async-trait` (0.1.92), `futures-core` and `futures-util` (0.3.34, Apache-2.0 or MIT), and `tokio` (1.54.1). The integrator adds them at fold.
- **O-WP21-4 TestTimezone loads `Asia/Tokyo`** through `gotime::load_location`, which reads the system zoneinfo. The case needs the zone file on the test machine.
- **O-WP21-5 Shared-suite cases that need a backend are untested here.** Every case in `database_test.rs` is unverified until WP-2-2 or WP-2-3 runs it. The gate for this WP does not run them.
