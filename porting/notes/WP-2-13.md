# WP-2-13 notes: schema conformance checker (provisional ids)

Crate `gorse-conformance`, module `schema` (`conformance/src/schema/`), tests in
`conformance/tests/schema.rs`. Base: integration head `12f19e4`; branch
`claude/project-thread-l30huk`. Provisional ids: the integrator renumbers them at
the fold.

## Result

Every backend agrees: the Go dump, the Rust dump and `contracts/schema/` are equal
for MySQL 8.0.46, PostgreSQL 10.0, MongoDB 6.0.28, SQLite (modernc) and the meta
store, and the Rust dump equals the Go dump for MariaDB 10.2.44. Redis 8 agrees on
`FT.INFO documents` after the normalisation in D-WP213-5. No store difference was
found. The one mismatch in the first run was in the test (a second `FT.INFO` read,
D-WP213-5), and it is fixed.

## Decisions

- **D-WP213-1 The dumper mirrors `schemadump`; the Go tool is unchanged.**
  `schemadump` creates its own databases and writes its dumps in the same run, so
  it cannot dump a database the Rust stores made. Adding a dump-only mode would
  change `contracts/tools/`, which is outside this WP's scope, so `schema::dump`
  reproduces each dump in Rust with the same queries and the same output format
  (`SHOW CREATE TABLE`, `sqlite_master`, `listCollections` and `listIndexes`
  with `v` removed, `FT.INFO` under RESP2 with Go's `%v`). The mirror is checked
  against the Go tool on the databases the Go run leaves behind: the MySQL search
  dump, both MongoDB dumps and the MariaDB dumps are byte-equal to the Go output.
  If the coordinator prefers the Go binary to do the dumping, a `-dump-only` flag
  in `contracts/tools/schemadump` is the change to ask for.

- **D-WP213-2 PostgreSQL is dumped inside the server container.** `pg_dump -s`
  runs through `docker exec` in `POSTGRES_CONTAINER` (default `storage-postgres-1`),
  as `dump-schemas.sh` does. The host's `pg_dump` is 16 and would not match the
  server's 10.0 output. The filters are the script's (`schema::dump::pg_clean`).

- **D-WP213-3 Separate databases.** Go writes `gorse_schema_*` and Rust writes
  `gorse_rs_schema_*` (`schema::init`), so neither build reads the other's
  database. Each test drops and creates its own databases before it starts.

- **D-WP213-4 A missing backend fails, it does not skip.** Each test needs its URI
  (`MYSQL_URI`, `MARIADB_URI`, `POSTGRES_URI`, `MONGO_URI`, `REDIS_URI`) and fails
  without it, as `conformance/README.md` requires. The Go tests skip instead.
  SQLite needs no server.

- **D-WP213-5 Run-dependent values and read counts.** Two rules, both applied to
  the Go side, the Rust side and the contract:
  1. `FT.INFO`'s `total_indexing_time` is wall-clock and is replaced by
     `<run-dependent>` (`schema::normalise_ft_info`). It is the only normalisation.
  2. `FT.INFO` increments `number_of_uses` on every call, so each state is read
     exactly once. The contract's `number_of_uses 1` is the first read after
     `Init`. The test reads the Go-created index once (by the Go run) and does not
     read it again.

- **D-WP213-6 MariaDB 10.2 has no frozen dump.** `contracts/schema` holds MySQL
  8.0 only. `schema_mariadb` compares the Go and Rust dumps with each other. The
  Go dump differs from the MySQL one in three ways, and each is the server, not the
  port: the server version line, `DEFAULT '0'` shown as `DEFAULT 0` for `double`,
  `labels` as `longtext` instead of `json`, and the multi-valued index
  `idx_collection_subset_categories` missing on MariaDB.

- **D-WP213-7 Samples are not in the schema check.** `schemadump` also writes
  `samples/*.json` (rows and encodings). WP-2-13 compares the schema files only,
  as its brief says. The rows are checked by the store WPs (WP-2-2, WP-2-3, WP-2-5,
  WP-2-6, WP-2-7), which the cross-reads cover.

## Open

- **O-WP213-1 Samples and Redis key layout.** The Go `samples/*.json` files and
  the Redis key listing (`samples/cache.redis.json`) are not compared yet. The
  coordinator's "key layout where applicable" covers `FT.INFO`; the key layout is
  the next step if the integrator wants it in this gate.
- **O-WP213-2 Mixed-version runs.** Only the Go and Rust builds at the pinned
  commit were run. Kvrocks and a six-node Redis cluster (the Go CI's
  compatibility job, brief Phase 2 exit gate) are not in this WP.

## Q-229 (schema equality)

Closed. The tables the Rust cache and data stores create equal
`contracts/schema/{mysql,postgres,sqlite}.sql` on MySQL 8.0.46, PostgreSQL 10.0 and
SQLite, and the search variants equal the Go reconcile output (`schema_mysql`,
`schema_postgres`, `schema_sqlite`).
