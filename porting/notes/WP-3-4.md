# WP-3-4 notes: CF logics and vector writer (provisional ids)

Ports: `logics/cf.go`, `logics/vector_writer.go` @ add21b5. Tests: `logics/cf_test.go` (2), `logics/vector_writer_test.go` (4), all passed by Go on add21b5 (`go test ./logics -run ...`, ok). Rust target: `crates/gorse-logics/src/{cf,vector_writer}.rs`.

## Deviations (X)

- **X-WP34-1 `MatrixFactorizationItems::add` takes `&mut self`.** Go's `Add` takes `itemsLock` and calls the HNSW from any goroutine. Gorse adds items from one goroutine (only `cf_test` builds one, see `contracts/model-blobs.md`), and Go's version can misplace an id under concurrent adds (the placeholder slot and the index position come from two different locks). The port has no lock and says so in its doc comment.
- **X-WP34-2 (resolved) The timestamp in a `MatrixFactorizationItems` blob is a gob `time.Time`.** The coordinator ruled that the bytes must match Go's, since a Go node may read a blob a Rust node wrote. `gorse-common`'s gob codec now has a `GobEncoder` value for `time.Time` (`MarshalBinary` bytes, length-prefixed), approved in the coordinator's relay of 2026-10-28T17:27Z. `contracts/tools/gobgolden` generates the golden cases (`time 0` to `time 3`, and six decode verdicts), and the golden test in `gorse-common` checks them against Go's bytes. `cf.rs` writes the timestamp with `write_gob` and reads it with `read_gob`, so `Error::Time` is gone.
- **X-WP34-3 `VectorWriter::clean` with no store.** Go calls `DeleteVectors` on a nil interface and panics. The port returns `vector database no database` (the same error `ensureCollectionLocked` returns), in line with X-7.
- **X-WP34-4 Items and users `unmarshal` replace all or nothing, and reject negative counts.** Go's `make` panics on a negative count and leaves a half-filled index on a later error; the port builds the new parts first and assigns them at the end (the X-22 pattern). Items are grown as the data arrives, not allocated from the count.
- **X-WP34-5 The sparse pruner's heap is a local port of `container/heap`, not `gorse_common::heap`.** `gorse_common::heap::PriorityQueue` holds `i32` values in an order that does not match `sparseVectorHeap` (value first, then larger index first). The local heap follows Go's `up`, `down` and `Fix` step for step, so NaN values (which break the ordering) end up where Go puts them.
- **X-WP34-6 `search` takes `n: usize`.** Go's `int` may be negative; a negative `n` has no Rust value here. No caller passes one.

## Go quirks reproduced (Q)

- **Q-WP34-1 An empty first vector leaves the dimension at 0.** `Add` sets the dimension only when it is 0, so an empty first vector keeps it 0, and the next vector sets it. The empty vector stays in the index. Reproduced as written.
- **Q-WP34-2 Duplicate indices in a sparse vector are all fed to the pruner.** `appendSparseVector` seeds `seen` from `vector.Indices`, so ids are skipped when their index is taken, but the input's own duplicates both enter the pruner. `Result` sorts them with `sort.Slice` (pdqsort), so the order of equal indices follows Go's algorithm, which `gorse_common::gosort` ports.
- **Q-WP34-3 NaN in a sparse vector.** An id whose idf is NaN passes the `idf <= 0` test and enters with a NaN value. NaN breaks the heap order, so which entries the pruner keeps depends on Go's exact sift steps. The port matches (see the oracle below).
- **Q-WP34-4 A sparse vector with more indices than values panics** in `appendSparseVector` (Go indexes past the end of `Values`); the port panics too.
- **Q-WP34-5 Searching an empty items index panics** (Go's `knnSearch`), as Q-61 records for the HNSW. `MatrixFactorizationItems::search` documents the panic.

## Evidence

- Differential oracle for the pruner and `appendSparseVector`: `conformance/tests/sparse_oracle.rs` runs Go live. It overlays `conformance/testdata/sparse_oracle_test.go` into package `logics` with `go test -overlay`, so the Go tree is not changed. Go makes 420 cases with seed 20261028: 400 pruner cases with ties, duplicate indices and NaN/±Inf, and 20 `appendSparseVector` cases that reach the 1024-entry limit. Rust matches all 420 cases bit for bit. Without the Go toolchain the test fails; it is never skipped. The earlier committed JSON snapshot and hand-run generator are gone.
- Mutation check (repeated on the conformance test): flipping the tie rule in `less` (`a.index > b.index` → `<`) makes `sparse_vectors_match_go` fail at case 4; the rule is restored, and the file is byte-identical to the commit.
- `test_vector_writer_batches_and_cleans` runs the writer on the real `xvec://` store: batch flush, the dimension of the first flush, dropping a vector of the wrong dimension, recreating a collection of another dimension, `clean`, and `clean` on a missing collection. Go has no writer test; the expected values come from reading `vector_writer.go`.
