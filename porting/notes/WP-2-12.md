# WP-2-12: proxy stores (notes)

Ports: `storage/data/proxy.go`, `storage/cache/proxy.go`, `storage/vectors/proxy.go`
(and their `*_proxy_test.go`), at the pinned commit `add21b5`.

Rust: `crates/gorse-storage/src/{data,cache,vectors}/proxy.rs`.

Ids are provisional. The integrator assigns the final `D-`, `Q-`, `X-` and `O-`
numbers in `PORTING.md` and `PORTING_NOTES.md`.

## Decisions (D-WP212-*)

- **D-WP212-1, shared suites through the proxy.** The coordinator approved an
  additive `pub(crate) run_through_proxy` in `data/database_test.rs` and in
  `cache/database_test.rs`. It runs the same cases in the same order as `run()`,
  minus the ones Go's `ProxyTestSuite` skips. `run()` is unchanged. Tests
  `refuses_init_scan_and_purge` (data and cache) assert that the proxy client
  refuses Init, Purge and Scan with Go's texts. The client-side refusals are
  `method Init is not allowed in ProxyClient` and `method Purge is not allowed in
  ProxyClient` (data), and `init`, `scan` and `purge is not allowed in proxy client`
  (cache). The suites through the proxy run only with `--features
  mysql,postgres,sqlite`, as the SQL suites they wrap do.
- **D-WP212-2, a NotFound error that keeps Go's text.** `data::Error` gains
  `Wrapped { kind, message }`. Its `Display` is the message and `kind()` reports
  `NotFound`. The proxy client returns it for a missing item or user, so the text
  is `item <id> not found` (and `user <id> not found`), as Go's
  `fmt.Errorf("item %s %w", ...)` gives it. Go's text is not shortened, since
  error text can reach REST bodies and logs. Test:
  `missing_item_reads_back_with_go_text`, plus the unit tests for the text.
- **D-WP212-3, `vectors.describe_collection` on a missing collection.** The server
  answers with gRPC `NotFound`. The client maps that code to a NotFound-kind error
  whose text is `collection <name>: not found`. The transcript pins the text
  `collection missing: not found`.
- **D-WP212-4, the error text of gRPC errors.** Go's client shows a status as
  `rpc error: code = <Code> desc = <msg>`, with Go's spelling of the code names
  (`Canceled`, not `Cancelled`). The Rust client builds the same text. Server
  errors that are not NotFound go out as `Status::unknown(err.to_string())`, as
  Go's server does.

## Quirks kept as Go has them (Q-WP212-*)

- **Q-WP212-1, timestamps.** `time_from_pb` of a nil timestamp is the Unix epoch
  (Go's `Timestamp.AsTime` on nil). `optional_time_from_pb` of nil is the zero time
  (Go's `timeFromPB`). The transcript pins both through the item, feedback and
  vector records.
- **Q-WP212-2, `GetItemStream` drops `time_limit`.** Go's client does not send it,
  so the Rust client does not either.
- **Q-WP212-3, empty repeated fields are nil on the wire.** An empty
  `categories` list reads back as nil in Go, and as `None` in Rust. So
  `ItemPatch` and `ScorePatch` cannot clear categories over the wire. The
  transcript shows `Categories: null` for an item stored with `[]`.
- **Q-WP212-4, the cache `Get` hides backend errors.** Go's server answers with no
  value and no error whenever the key does not exist, even when the backend
  reported an error with it. So a failing `get` reads back as a missing key. The
  Rust server does the same (`a_failing_get_reads_as_a_missing_key_through_the_proxy`).
- **Q-WP212-5, the vector distance.** A distance number that is not one of the
  three known ones is an error with the text `distance method not supported`, the
  text Go's `distanceFromPB` gives (`distances_convert_both_ways_and_refuse_unknown`).

## Deviations (X-WP212-*)

- **X-WP212-1, contexts do not cross the wire.** Go passes the call's context into
  the backend. The Rust server gives the backend a background context. A client
  that goes away drops the call's future, which stops the work the same way.
- **X-WP212-2, where Go panics.** Go's server dereferences `scan_options`
  unchecked, so a request without them panics. The Rust server returns an error
  there. Go's client always sends the options, so the oracle does not reach this
  case. Missing `condition` or `patch` likewise become an error or a default.
- **X-WP212-3, cache scan buffer.** `scan_scores` on the Rust server pushes into an
  unbounded channel, so the backend is not paused by the client's reads. Go's
  stream is paced by the send. Memory use can grow with a slow reader.
- **X-WP212-4, malformed JSON text.** A labels blob that is not valid JSON fails
  with serde's message, not Go's `encoding/json` text. Empty bytes give Go's
  `unexpected end of JSON input` text, as Go does.
- **X-WP212-5, base commit.** The brief names `25c5bb81` as the base. The
  integration head is `12f19e4`, and `25c5bb81` is its ancestor. The branch
  `claude/wp-2-12-proxies` starts from `12f19e4`.

## The wire oracle (O-WP212-*)

- **O-WP212-1, one scenario, two languages.** `contracts/tools/proxygolden` runs a
  66-step scenario (data 32, cache 19, vectors 15) through Go's proxy clients and
  servers, and writes `crates/gorse-storage/tests/data/proxy_transcript.txt`.
  `crates/gorse-storage/tests/common/proxy_scenario.rs` runs the same steps through
  the Rust proxy clients. Each step's line is its name, a tab, then `{"ok":…}` or
  `{"err":…}`, with keys sorted and integral floats written as integers.
- **O-WP212-2, both directions.** `tests/proxy_wire.rs` replays the scenario
  against the Rust servers in-process, per store, and compares with the golden
  lines. The live checks use the `proxy_peer` example:
  `go run ./contracts/tools/proxygolden -rust-server …/proxy_peer` runs Go's
  client against the Rust server, and `-rust-client …/proxy_peer` runs the Rust
  client against Go's server. Both print `transcript matches`. A mutated golden
  line makes the `-rust-client` check fail at that line.
- **O-WP212-3, what the transcript does not cover.** The `Updated` column is
  checked as Go sets it (equal to the timestamp at insert). Float values are
  chosen to be exact in f32 and f64, so the two languages print them the same.
  Search (`SearchItems`), `GetLatestItems` and the Milvus, Qdrant and Weaviate
  stores are not in the scenario.
