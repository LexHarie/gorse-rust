# WP-1-14 notes: storage core (storage/errors.go, options.go, scheme.go)

Provisional ids; the integrator renumbers them into `PORTING_NOTES.md` and
`PORTING.md`. The Rust target is `crates/gorse-storage-core` (`errors.rs`,
`options.rs`, `scheme.rs`, `json_contains.rs`, `mysql_dsn.rs`,
`gorm_naming.rs`). The Go library code that `scheme.go` depends on is ported
into `gorse-common`: `gourl` (net/url), `gostrings` (strings.Replacer),
`goutf8` (unicode/utf8), `gojson` (encoding/json decoding), and, through D-52,
`gostrconv`'s `ParseFloat` and `ParseBool`. `gostrconv`'s integer parsing and
`gonet` came earlier as part 1 (merge 090e9dd).

The Go oracle data was written with go1.27.0, the toolchain that add21b5's
`go.mod` selects. Each tool regenerates byte-identical files:

```
go run ./contracts/tools/storagegolden \
  -out crates/gorse-storage-core/tests/data/storage_golden.json \
  -gojson-out crates/gorse-common/tests/data/gojson_golden.json
go run ./contracts/tools/urlgolden -out crates/gorse-common/tests/data/gourl_golden.json
go run ./contracts/tools/strconvgolden \
  -pow10tab crates/gorse-common/src/gostrconv/pow10tab.rs \
  -out crates/gorse-common/tests/data/strconv_golden.json
```

These commands belong in the regeneration list of `contracts/README.md`,
which this WP does not edit. `storagegolden` runs each `json_contains` case
in a child process, because a panic inside the function leaves the Go
connection locked. It takes MySQL `loc=` zones from the stand-in GOROOT that
`timegolden` writes, so the Rust tests need no system tzdata.

## Plan corrections

- **C-WP14-1 WP-1-14 depends on WP-1-9.** `work-packages.md` lists no
  dependency. However, `Options.ConnMaxLifetime` is a `time.Duration`, and
  the MySQL DSN's `loc` parameter goes through `time.LoadLocation`, its
  timeouts through `time.ParseDuration`. The port uses `gorse_common::gotime`.
- **C-WP14-2 `scheme.go` needs Go standard library ports that the plan does
  not list.** Gorse's results and errors depend on their exact behaviour:
  - `net/url` (`AppendURLParams`, and every store that parses a URL). This
    is `gourl`, with `ParseRequestURI`, `Values`, the escape functions, and
    the `urlstrictcolons` and `urlmaxqueryparams` GODEBUG settings, which it
    reads as Go does.
  - `strings.Replacer` (gorm's names, and later the Redis and xvec stores).
    This is `gostrings`.
  - `encoding/json` into `any`, `[]any` or `map[string]any`
    (`json_contains`, labels, viper's config codec for WP-1-15). This is
    `gojson`.
  - `unicode/utf8`. This is `goutf8`.

  They live in `gorse-common` so that later packages share them. Each has a
  `Ports:` header that names the go1.27.0 files.
- **C-WP14-3 `scheme.go` needs parts of two third-party libraries.**
  - `AppendMySQLParams` round-trips the DSN through go-sql-driver/mysql
    v1.9.3's `ParseDSN` and `FormatDSN`. That is `mysql_dsn.rs` (MPL-2.0, a
    file-level licence; the licence text is in
    `crates/gorse-storage-core/licenses/`).
  - `NewGORMConfig`'s `NamingStrategy` decides every table, column, index
    and constraint name that a Go node creates. That is gorm v1.31.1's
    `schema/naming.go` in `gorm_naming.rs` (MIT, licence alongside).
  - `crypto/sha1` (gorm's `formatName`) adds a dependency, `sha1` 0.11.0,
    with a row in `porting/crate-selection.md`.
- **C-WP14-4 Go 1.27's `encoding/json` is the v2 decoder.** In go1.27,
  `GOEXPERIMENT=jsonv2` is on by default, so `json.Unmarshal` is v1's API
  over v2's implementation. The order of operations changes, and so do some
  texts:
  - The whole input is checked for syntax first; then the top-level kind
    ("json: cannot unmarshal array into Go value of type
    map[string]interface {}"); then the value is decoded.
  - A float overflow names its path ("json: cannot unmarshal number 1e400
    into Go struct field .master.port of type float64").
  - A duplicate name replaces the earlier value whole: `{"a":{"b":1},"a":{"c":2}}`
    decodes to `{a:{c:2}}`.

  `serde_json` differs on each of these points, so `gojson` is a hand port,
  with objects in an `IndexMap` (`indexmap` 2.14.2, new row in
  `crate-selection.md`).
- **C-WP14-5 The driver glue is Phase 2 work.** Two pieces need a live
  connection, which WP-1-14 has none of:
  - registering `json_contains` on SQLite connections (the `rusqlite` choice,
    D-18);
  - `ProbeMySQLIsolationVariableName`'s query.

  WP-1-14 ports the logic. The SQL stores (WP-2-2, WP-2-6 and, for SQLite,
  WP-2-11) wire it up, with the obligations in O-WP14-1.

## Decisions

- **D-WP14-1 A `json_contains` element that Go cannot hash is an error, not a
  panic.** In Go, an array or object element panics inside the `map[any]`
  insert or lookup, and the panic leaves the connection locked. Here it is
  `json_contains::Error::Unhashable`, carrying the text Go's panic prints
  (Q-WP14-2).
- **D-WP14-2 `gojson` objects keep document order.** Go's maps have no order,
  so any order matches Go. Document order makes iteration deterministic. A
  duplicate name keeps its first position and takes its last value.
- **D-WP14-3 Only `gojson`'s error texts are ported.** Go also returns a
  partial value along with an error, and the error carries byte offsets.
  Neither is ported, because only the texts reach Gorse.
- **D-WP14-4 Go strings are bytes.** URLs, DSNs, query keys and values, table
  names and gorm names are `Vec<u8>` / `impl AsRef<[u8]>`. Gorm's mixed
  byte and rune indexing can produce invalid UTF-8 exactly where Go's does.
  `DsnError`'s `Display` shows U+FFFD, and `DsnError::error_bytes` gives
  Go's bytes.
- **D-WP14-5 A non-UTF-8 MySQL `loc` name.** `LoadLocation` takes a `&str`.
  A name with `..`, a leading `/` or a leading `\` is `InvalidName`, as in
  Go. Any other non-UTF-8 name is `UnknownTimeZone`: zone files have ASCII
  names, so Go finds none, and the golden cases confirm it.
- **D-WP14-6 `probe_mysql_isolation_variable_name` takes the query as a
  closure.** Go opens a connection with the driver. Here the caller passes a
  function that runs the query on the parsed `Config`. The DSN is parsed
  first, as Go's `sql.Open` (`OpenConnector`) does, so a DSN error comes
  before any connection.
- **D-WP14-7 Only gorm's singular names are ported.** `NewGORMConfig` always
  sets `SingularTable: true`, so `jinzhu/inflection`'s plurals are not
  ported, and neither are `SchemaName` or `RelationshipFKName` (Gorse has no
  relationships). `GormConfig` has no logger: Go sets a silent one.
- **D-WP14-8 Only the DSN side of go-sql-driver/mysql is ported.** The
  connection side (`Logger`, `DialFunc`, `BeforeConnect`, `Config.Apply`) is
  not. A failed `parse_dsn` returns no partial `Config`. A `strict`
  parameter panics with Go's message, as in v1.9.3.
- **D-WP14-9 `Opt` is a boxed `Fn(&mut Options)`** (Go's `func(*Options)`).
  The counts are `i64`, because Go's `int` is 64 bits on every platform
  Gorse ships for. `apply_sql_pool` takes a `SqlPool` trait standing in for
  `*sql.DB`.

## Quirks reproduced

- **Q-WP14-1 go1.27 `ParseFloat` past 800 digits.** `decimal.set` keeps 800
  digits, but it takes the decimal point from the capped count. A mantissa
  longer than that with a nonzero tail therefore parses wrongly. The bits of
  `ParseFloat(s, 64)`, matched by the port at both `SetOptimize` settings:

  | s | Go bits |
  |---|---|
  | `"9007199254740993" + "0"*790 + "1e-791"` | `41cad7f29abcaf49` (9.007199254740993e+08) |
  | `"9007199254740993" + "0"*900 + "1e-901"` | `2af42c7ff0054685` (9.007199254740992e-102) |
  | `"9007199254740993" + "0"*700 + "1e-701"` | `4340000000000001` |
  | `"0." + "0"*900 + "1e-901"` | `0` |

  A correctly rounding parser gives `4340000000000001` for the first three.
  `gojson` reaches this through any JSON number that long.
- **Q-WP14-2 Unhashable `json_contains` elements have two texts.**
  - Inserting into a map, or looking up in a non-empty one, goes through
    `typehash`: `runtime error: hash of unhashable type []interface {}` (or
    `map[string]interface {}`).
  - A lookup in an empty map goes through `mapKeyError`: `hash of unhashable
    type: []interface {}`.

  `-0` and `0` are the same key.
- **Q-WP14-3 modernc's SQLite boundary.** This is what Go sees, and the Rust
  SQLite glue must reproduce it:
  - A `TEXT` argument arrives through `libc.GoString`, so it ends at its
    first NUL (`modernc_text`). A `BLOB` keeps every byte, `INTEGER` is
    `int64` and `REAL` is `float64` (both are "unsupported type").
  - A function error passes through `libc.CString`, so it is cut at a NUL,
    and is reported as `SQL logic error: <msg> (1)`, or `SQL logic error
    (1)` when the message is SQLite's own (`modernc_error_text`).
  - A `bool` result is integer 1 or 0.
  - A nil `[]byte` binds as `NULL`.
- **Q-WP14-4 `AppendURLParams` re-encodes the whole query.** The keys come
  out sorted (`Values.Encode`), and an existing pair that does not parse is
  dropped silently. A Windows path parses as a URL with scheme `c`, and the
  ported Go test pins it.
- **Q-WP14-5 Raw bytes in MySQL DSN errors.** Some error texts carry the
  DSN's bytes unchanged, invalid UTF-8 included: an unknown network's default
  address, the TLS config and server public key names, bool values, time
  zones, `timeTruncate`, and a reserved TLS key.

## Obligations for Phase 2

- **O-WP14-1** The SQLite stores register `json_contains` as deterministic,
  with two arguments, on every connection (Q-25). The glue must:
  - map SQLite values to `json_contains::Arg`, `TEXT` through
    `modernc_text`;
  - return `NULL` for `None` and an integer for the bool;
  - report errors with `modernc_error_text`;
  - bind an absent blob as `NULL`.

  How to surface `Error::Unhashable`, where Go locks the connection, is that
  WP's call: a query error is the natural one.
- **O-WP14-2** The MySQL stores call `probe_mysql_isolation_variable_name`
  with their driver, and `apply_sql_pool` on their pool.

## Mutation checks

23 hand mutations of `storage-core` and `gojson` were each killed by the
golden tests, for example:
- the `documents` table renamed;
- `q.set` for `q.add`;
- `-0` hashed apart from `0`;
- no NUL cut;
- `and_modify` in `AppendMySQLParams`;
- the empty-map panic text;
- the `"array"` kind.

Five raw-byte DSN error mutations at first survived. They led to the
`mysqlRawByteDSNs` golden cases, and now each is killed.

Three `ParseFloat` mutations were each killed: no 800-digit cap, `MaxFloat64`
on range errors, and hex rounding half up.
