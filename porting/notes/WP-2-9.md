# WP-2-9: vector backends (Qdrant, Milvus, Weaviate)

Ports `storage/vectors/{qdrant,milvus,weaviate}.go` and their `_test.go` files to
`crates/gorse-storage/src/vectors/{qdrant,milvus,weaviate}.rs`, behind the features
`qdrant`, `milvus` and `weaviate`. Branch `claude/wp-2-9-vector-backends`, from
`claude/phase-0-contracts-lqc6fr` at 12f19e4.

The three stores share one `open()` dispatch, one `not_supported` helper, one set of
Cargo features and one `Cargo.lock`, so they land as one commit. Per-backend commits
would not build on their own.

## Provisional ids

The integrator assigns the D-, Q- and O- numbers on merge.

- **P-1 Qdrant client is `qdrant-client` 1.20.0.** `porting/crate-selection.md` said
  1.19.0. 1.20.0 is the latest stable release. Go's module pins `qdrant/go-client`
  v1.18.2. Against the 1.20.0 test server the 1.18.2 client only warns.
- **P-2 Milvus and Weaviate are hand-written REST adapters**, as D-17 says. No change
  to D-17 is needed.
- **P-3 Errors wrap the storage sentinels as Go's `%w` does.** Every NotSupported
  error from the three stores is `Error::Storage { kind: NotSupported, .. }` through
  `vectors::not_supported`, so `kind()` matches Go's `errors.Is`. Before the fix,
  Qdrant and Weaviate returned `Error::Other` for these.

## Verified against Go

- Object ids: Qdrant point ids and Weaviate object ids are UUID v3 (MD5 over
  `NAMESPACE_URL`) of the vector id, as Go does.
- Milvus schema: `id` VarChar primary key, `categories` Array of VarChar,
  `hidden` Bool, `timestamp` Int64, `vector` Float16Vector or SparseFloatVector.
  Indexes: HNSW (`M` 16, `efConstruction` 200), IVF_RABITQ, IVF_PQ, IVF_SQ8
  (`nlist` 128), SPARSE_INVERTED_INDEX (`drop_ratio_build` 0), STL_SORT on
  `timestamp`. Search parameters: `ef` 100, `nprobe` 8, `refine_k` 1.
- Weaviate: class names capitalised, `vectorIndexConfig` with `sq`, `pq` or `rq`,
  GraphQL `where` clauses as Go's `WhereBuilder` writes them.
- Qdrant: quantization config as Go's `qdrantQuantizationConfig`. RQ bits 1, 2, 4;
  PQ bits 8, 4, 2, 1 mapped to `X4`, `X8`, `X16`, `X32`; SQ bits 0 or 8.
- Qdrant normalises Cosine vectors on write, in Go and in Rust alike. The cross-read
  compares dense values by direction.

## Deviations, and why

1. **Milvus index parameters are unnested.** The REST gateway returns an index's own
   parameters as a JSON string under `params`. Go's gRPC client sees them flat. A probe
   with Go's client printed
   `map[index_type:IVF_PQ m:4 metric_type:IP nbits:8 nlist:128]`. `index_params`
   unnests the JSON, so `describe_collection` reads `m` and `nbits` the way Go does.
2. **Milvus `description` goes at the top level of the create request.** A
   `description` inside `schema` is dropped by the REST gateway. A probe showed this.
3. **Milvus category filters are JSON-escaped literals**, not template parameters
   (Go's `WithTemplateParam`). For string categories the filter means the same thing.
4. **Milvus query-by-ids quotes ids with JSON escapes.** Go quotes them raw. The text is
   identical for ids without quotes or backslashes.
5. **Milvus waits by polling.** Go's `Await` becomes a 100 ms poll of
   `/indexes/describe` (`Finished`, `Failed`) and `/collections/get_load_state`
   (`LoadStateLoaded`).
6. **Milvus sparse vectors** travel as JSON objects from dimension to value. They are
   read back sorted by dimension, as Go's sparse embeddings are.
7. **Weaviate** sends batches over REST, as Go does (its `Open` sets no gRPC config).
   Describe reports no dimension, as Go's does not. Sparse vectors are not supported,
   and Go's `TestSparse` skips for Weaviate, so the Rust case is `#[ignore]`d with
   that reason.
8. **Qdrant `delete_collection`** checks the response's `result` and errors for a
   missing collection, as Go's client does. Before the fix it returned Ok.
9. **Qdrant turbo-quant bit names.** Go's `TurboQuantBitSize` enum has no 8-bit value,
   and messages print its names as `String()` does (`Bits1`, `Bits1_5`, `Bits2`,
   `Bits4`). `go_turbo_bits_name` does the same.

## Test environment (not code)

- Qdrant server 1.20.0 (`qdrant://127.0.0.1:6334`).
- Weaviate `semitechnologies/weaviate:1.35.7` (`cr.weaviate.io` is refused from this
  container).
- Milvus v2.6.9 with etcd `gcr.io/etcd-development/etcd:v3.5.25` (`quay.io` is
  refused). Milvus runs with `COMMON_STORAGETYPE=local` and `MQ_TYPE=rocksmq`,
  because embedded etcd cannot run in distributed mode. Docker Hub returned 429 once
  and succeeded on retry.
