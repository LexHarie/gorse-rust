## Deviations and findings
1. The memory gauges (`MemoryInUseBytesVec`, master/tasks.go 234 to 245) are set from the port's DeepSize,
   `ranking_dataset_size` and `click_dataset_size` in tasks.rs. Their values cannot equal Go's `sizeof.DeepSize`:
   Go's walk follows Go's layout, slice capacities and map buckets, and the port counts struct sizes and heap bytes
   by length. The index, the dictionaries, the timestamp and negative lists, and the label values are not counted.
   The labels are Go's, including the crossed pairing (ranking splits under `collaborative_filtering_*`, click
   splits under `ranking_*`). `test_load_dataset_sets_memory_gauges` checks each label is above zero, that it
   measures the split it is named for, and that it grows when the dataset grows. The eleven gauges of master/tasks.go
   159 to 214 are set in `load_dataset_in` and checked by `test_load_dataset_sets_gauges` (O-88).
2. Dataset items keep their stored labels through the `Value` view. FP16 label conversion is not applied to
   `Labels`, and embeddings are derived from the converted `Value`. The O-75 test covers the processed view.
3. Positive CTR samples are sorted. Go's order is random, so the sort fixes one order.
4. The ranking pipeline uses its own tracer, because `Monitor` is not `Clone`.
5. Scan deletions run after the scan finishes, not during it.
6. DeepSize is computed from local constants.
7. Changes outside this WP's crates, on this branch in the WIP commits, for review:
   - gorse-model: serde derives on the CTR metric and model types in `ctr/model.rs`, and `Model: Send` in `cf/model.rs`.
   - gorse-dataset: `Clone` on `Dataset` types in `dataset.rs`.
8. master_test.go has no test cases in Go. Its fixture is in `crates/gorse-master/src/test_support.rs`.
9. SQLite bulk insert fails above SQLite's 32,766 bind limit ("too many SQL variables"). A 12,000-row batch fails in
   one call. The parallel load test inserts in chunks of 1,000. This is a defect in the sqlite data backend, another
   WP's crate. It is reported here and not fixed in this WP.
10. X-199 (feedback reads precede the update) is guarded, not proven by mutation. The logics `add` takes `&[i32]`,
    so an in-place sort cannot happen in the Rust code. `item_feedback_is_read_in_order_and_not_reordered` pins the
    order. It cannot fail through a mutation that the types already prevent.
11. O-75 mutation check: emptying the processed `Ids` made the tags test fail, as intended. The change was reverted.
12. Retention mutation check: `take(2)` changed to `take(1)` made `test_remove_out_of_date_models` fail, as intended.
    The change was reverted.
13. `Progress` does not derive `PartialEq`. The rpc test compares its fields one by one.
14. TDD honesty: the rpc and tasks implementations were drafted before their tests. The rpc tests passed on their first
    run, so they were not seen failing.
15. The Go `MatrixFactorizationUsers.Marshal` writes entries in map order, which is random. Two Go runs with equal
    embeddings therefore write different bytes. The mixed-cluster training test decodes the blob into a map and
    compares the entries exactly, with f32 equality. It first checks that two Go runs agree.
16. The mixed-cluster log check fails on any ERROR line except `failed to evaluate column expression`. Go logs that
    same line for users with no embedding (logics/item_to_item.go:157 in Go).

## Design decisions
- Master is held in Arc; tonic MasterServer::from_arc(Arc<Master>) with `impl Master for Master` in rpc.rs.
- Stores data/cache/vectors are RwLock<Arc<dyn Database>> so tests and Serve can set them (Go sets them in Serve and tests).
- Splits passed to ModelSearch need 'static owned values: a local Arc wrapper implementing CfSplit/CtrSplit by delegation (in tasks.rs).
- serve() does everything except HTTP (WP-4-4 adds StartHttpServer).
