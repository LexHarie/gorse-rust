## Plan corrections

- **C-WP19-1 `time` is a hand port of Go's `time` package, not `chrono`.**
  `porting/crate-selection.md` row "time" picks `chrono` 0.4.45 with "Go
  layouts implemented by hand on top". What Gorse needs from `time` is Go's
  exact text: `Time.String()` with the monotonic suffix `m=+…` (the cache
  stores it, Q-1), Go layouts in both directions with Go's `ParseError` texts
  (dateparse builds a layout and calls `time.Parse`), `Duration.String` and
  `ParseDuration` (configs), `MarshalJSON`/`UnmarshalJSON`, and
  `LoadLocation`'s search order, TZif reader and errors. Once layouts, parsing,
  the calendar arithmetic Go wraps on overflow and the zone reader are ported,
  `chrono` contributes nothing (it has no monotonic reading and reads zones
  differently), so it is not a dependency. The row should read "hand port of
  Go's `time` (`gorse_common::gotime`)"; not edited here.
- **C-WP19-2 dateparse needs `strconv.Quote`.** Its errors quote the input with
  `%q`, so `gorse_common::gostrconv` ports `Quote`, `AppendQuote`,
  `QuoteRune` and `IsPrint` (with Go's print table, generated). WP-1-14
  extends the same module with `ParseInt`, `ParseUint` and `Atoi`; later ports
  that quote Go strings should use it.

## Decisions

- **D-WP19-1 Go strings are bytes.** Parsers take `impl AsRef<[u8]>` and accept
  any bytes, as Go does; results Go can return as invalid UTF-8 are `Vec<u8>`
  (`dateparse::parse_format`). Errors keep Go's exact bytes behind accessors
  (`dateparse::Error::error_bytes`, `gotime::ParseError::value` and friends);
  their `Display` replaces invalid UTF-8 with U+FFFD.
- **D-WP19-2 Go's shape.** Go's `int` is `i64`, Go's wrapping arithmetic wraps,
  `time.Date`/`time.Unix`/`time.Now` are free functions (`date`, `unix`,
  `now`), the mutable `time.Local` is `local()`/`set_local()`. `Location` is an
  `Arc`; `==` on `Location` and on `Time` compares like Go's `==` (pointer
  identity of the location), `Time::equal` compares instants and
  `Location::deep_equal` stands in for `reflect.DeepEqual`.
- **D-WP19-3 Tables Go computes are generated from Go**, not derived from
  Rust's Unicode data: `dateparse/tables.rs` (`unicode.IsLetter`, `IsDigit`,
  `ToLower` over every code point, Unicode 17.0.0), `gostrconv/tables.rs`
  (`strconv.IsPrint`), `gotime/errno.rs` (`syscall.Errno` texts that
  `LoadLocation` reports).
- **D-WP19-4 Hermetic zone data for tests.** The tool writes the TZif files of
  the zones the tests use to `tests/data/zoneinfo/` and a stand-in GOROOT zip
  (`tests/data/goroot/lib/time/zoneinfo.zip`, Go's uncompressed format) from
  go1.27.0's own `lib/time/zoneinfo.zip`. The tests turn the system zone
  directories off (`internal::disable_platform_sources`) and point the GOROOT
  fallback at the stand-in, so results do not depend on the machine's tzdata.
- **D-WP19-5 Golden corpus.** `gotime_golden.json`: 400 `Format` cases over 38
  layouts and 19 `Local` zones, 2061 `Parse`/`ParseInLocation` cases, 351
  `Date` normalizations, 26 `Duration.String`, 77 `ParseDuration`, 60
  `UnmarshalJSON`/`UnmarshalText`. `dateparse_golden.json`: 17615 cases of
  `ParseAny`, `ParseIn`, `ParseLocal`, `ParseStrict` and `ParseFormat` over
  dateparse's own test inputs, edge cases, the values Go nodes write to the
  cache and a seeded corpus of mutations, in several `Local` zones and with each
  option. Every case must match exactly: the instant, location name and offset,
  or the error text, or the layout.

## Quirks reproduced

gotime is a line-by-line port; these are the Go behaviours Gorse can observe.

- **Q-WP19-1 `Time.String()` ends in ` m=±<seconds>` for times from `now()`**
  (Q-1). The reading counts from the process clock start; `Round(0)`, `In`,
  `Local` and `UTC` drop it, as in Go.
- **Q-WP19-2 Malformed zone data under `$ZONEINFO` is not reported.**
  `LoadLocation` assigns the read's nil error, not the parse's, to `firstErr`
  (`zoneinfo.go`), so a corrupt file there falls through to the system sources
  and the final error is theirs. Ported as is.
- **Q-WP19-3 `$ZONEINFO` is read once per process**, at the first
  `LoadLocation`; `Local` is read once from `$TZ` (else `/etc/localtime`, else
  UTC named "UTC").

dateparse (each is reproduced and covered by the golden corpus or the ported
tests unless marked):

- **Q-WP19-4 Indices are byte positions**; after a multi-byte character the
  index sits on its last byte. The time-state loop reads raw bytes as
  characters, so byte 0xC3 counts as the letter `Ã`; the digit-slash check reads
  the byte after the slash the same way (not covered by the corpus).
- **Q-WP19-5 Restarts drop the options.** `"Mon "`, `"Tue "` and the other
  weekday prefixes restart the parse without the caller's options (not covered
  by the corpus); st/nd/rd/th suffixes are removed by a restart; a comma in the
  time becomes a period by a restart; a colon before milliseconds is rewritten
  to a period in the input itself; `"jan."` becomes `"jan"` only when the
  period is at index 4.
- **Q-WP19-6 Lowercasing is Go's `unicode.ToLower`:** `İ` lowers to `i` and the
  Kelvin sign to `k`, so `"AprİL 8, 2009"` yields the layout `"JanuaryL…"` and
  fails.
- **Q-WP19-7 Each `parse()` re-applies the full month name and the weekday
  skip** to the layout.
- **Q-WP19-8 `RetryAmbiguousDateWithSwap`** runs on whichever parser came back
  (including one from a restart without options), re-parses the final input in
  `Local`, replaces the parser even with nil while keeping the original error,
  and looks for "month out of range" anywhere in the error text.
- **Q-WP19-9 An "AM" suffix is written into the layout as "PM".**
- **Q-WP19-10 All-digit inputs:** 13- and 16-digit timestamps wrap on overflow;
  lengths 14, 8 and 4 become fixed layouts whatever the digits; under 4 digits
  gives "too short" with the raw bytes.
- **Q-WP19-11 `ParseFormat` can return invalid UTF-8.**
- **Q-WP19-12 "TZ offset not recognized"** fires for offsets of 0, 1, 2 or 4
  characters and quotes the local copy of the input.
- **Q-WP19-13 An unknown period-month** returns a non-nil parser together with
  the error.

## Deviations

- **X-WP19-1 The monotonic clock starts at first use**, not at process start:
  Go takes `startNano` at package init, Rust has none. `gotime::init_process_clock()`
  starts it; nodes call it first thing in `main`. The `m=+` values differ
  between any two processes anyway.
- **X-WP19-2 No build-time GOROOT.** Go's `runtime.GOROOT()` falls back to the
  GOROOT baked into the binary, so a Go node finds `lib/time/zoneinfo.zip` on a
  machine with the toolchain. A Rust binary has none: the zip fallback applies
  only with `$GOROOT` set or after `internal::set_default_goroot`. The system
  zone directories and `$ZONEINFO` work as in Go. Gorse's release images are
  `FROM scratch` with no toolchain and no tzdata (`cmd/*/Dockerfile`), so
  there only UTC and fixed zones load, in Go and in Rust alike.
- **X-WP19-3 `time/tzdata` (embedded zone database) is not ported**: Gorse does
  not import it.
- **X-WP19-4 A truncated zip central directory** is reported as `corrupt zip
  file`; Go slices without a length check and panics.
- **X-WP19-5 `serde::Deserialize` for `Time`** receives the unescaped string,
  where Go's `UnmarshalJSON` sees the raw JSON bytes. `Time::unmarshal_json`
  takes raw bytes and is exact; serde errors carry serde_json's position
  suffix.
- **X-WP19-6 Errors are `Result`s.** Go returns `(zero Time, err)`; the ported
  Go tests map an error back to `Time::default()` where Go asserts the zero
  time.
- **X-WP19-7 dateparse API shapes:** `parse_in` takes `&Location` (Go's
  `ParseIn(s, nil)` is `parse_any`); `ParserOption` is an enum, not a function
  value; unused Go constants (two date states, two time states, `offsetlen`) are
  left out. Behaviour is the same.
- **X-WP19-8 Panics.** Where Go panics (index out of range, nil parser), the
  port panics at the same inputs with Rust's message; Go's deferred retry while
  panicking is not emulated (the outcome is still a panic). The golden test
  requires a panic exactly where Go panics.

## Go tests

Ported case for case, with the same assertions:

- `time/format_test.go` → `tests/gotime_go_format.rs` (32 tests),
  `time_test.go` and `mono_test.go` → `tests/gotime_go_time.rs` (55),
  `zoneinfo_test.go`, `zoneinfo_unix_test.go` and `abs_test.go` →
  `tests/gotime_go_zoneinfo.rs` (22), `example_test.go` →
  `tests/gotime_go_example.rs` (the 39 examples with an `// Output:` comment,
  compared the way `go test` compares them, plus a test of that comparison;
  the 7 examples without one, `Duration`, `Since`, `After`, `Sleep`, `Tick`,
  `Month` and `NewTicker`, are not run by `go test` either).
- dateparse `parseany_test.go` → `tests/dateparse_go.rs` (all 9 tests, every
  table row), plus `storage/cache/database_test.go` lines 92-99 (the cache
  `Time` round trip).
- `tests/gotime_golden.rs` and `tests/dateparse_golden.rs` replay the goldens.

Not ported, and why:

- `TestCountMallocs`, `TestUnmarshalTextAllocations`: allocation counts. They
  need a counting global allocator (an `unsafe impl`, denied by the workspace),
  and Rust's allocations are not Go's escape-analysis counts.
- `TestConcurrentTimerReset`, `TestConcurrentTimerResetStop`, `sleep_test.go`,
  `tick_test.go`, the `<-After(1)`/`<-Tick(1)` lines of
  `TestHasMonotonicClock`: timers and tickers, which gotime does not have
  (Gorse uses tokio's).
- `TestInternal`: it runs the `abs_test.go` cases, ported with that file.
- `TestLinkname` (`linkname_test.go`): checks the `time.Time.abs`, `absClock`
  and `absDate` shims Go keeps for packages that `go:linkname` into `time`;
  gotime has no linkname surface.
- `tzdata_test.go` `TestEmbeddedTZData`: `time/tzdata` is not ported (X-WP19-3).
- `zoneinfo_android_test.go`, `zoneinfo_windows_test.go`: other platforms.

How the test ports differ from Go's harness:

- Go tests that set environment variables run as child processes of the test
  binary (`common::run_in_child`): Rust 2024 makes `set_var` unsafe and the
  workspace denies unsafe code. Each child runs the part of the Go test after
  its change. `TestEnvTZUsage` changes `$TZ` 11 times with
  `ResetLocalOnceForTest` between; the port runs one child per value, all 11
  checks kept.
- `ForceUSPacificForTesting` loads America/Los_Angeles from the stand-in GOROOT
  zip; Go's tests read the system zone directories wherever they do not call
  `DisablePlatformSources`, the port turns them off for the whole binary
  except in the `TestEnvTZUsage` children.
- `testing/quick` (seeded from the clock) becomes a fixed-seed splitmix64 with
  Go's counts and distributions, so a failure reproduces.
- `TestFormatAndParse`: Go's property builds `Unix(sec/2, 0)` and skips every
  `sec` for which `t1.Unix() != sec`, so only `sec == 0` is ever checked. The
  port keeps the random loop and adds an explicit `f(0)` so that one checked
  case always runs.
- The fuzz targets `FuzzFormatRFC3339` and `FuzzParseRFC3339` run their seed
  corpora, as `go test` does without `-fuzz`; `t.Skipf` ends that seed's run
  and is printed as a skip.
- `TestTruncateRound`: `big.Int.DivMod` becomes `i128::rem_euclid`; Go's
  `uint(negative)` shift giving 0 is mirrored by hand.
- `TestTimeGob` round-trips the payload through `MarshalBinary`/
  `UnmarshalBinary` (what `GobEncode`/`GobDecode` call) without the gob stream
  framing; `TestInvalidTimeGob` and `TestNotGobEncodableTime` run each case
  once since the gob methods are those same functions.
- `TestUnmarshalInvalidTimes` checks `unmarshal_json`, then serde_json with its
  position suffix removed, then `unmarshal_text`. `TestMarshalInvalidTimes`:
  Go's `AppendText` returns nil on error; here the buffer stays empty.
- `TestDefaultLoc`'s "Nanosecond" case compares `Hour()` in Go; kept.
- dateparse: zones load from the stand-in GOROOT zip; `TestInLocation`'s
  `time.Local = nil` is emulated as UTC (neither call made then reads Local);
  `TestPreferMonthFirst` and `TestRetryAmbiguousDateWithSwap` run with
  America/Denver, which `TestInLocation` leaves behind when Go runs the file in
  order; `TestPStruct` reaches the parser through `dateparse::internal`. The
  cache round trip runs in the Go test environment's Local plus UTC, Shanghai,
  Kathmandu and Chatham, where Go uses the machine's Local only.
