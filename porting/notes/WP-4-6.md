# WP-4-6 notes: client and `gorse-cli`

Provisional ids, folded into `PORTING.md` and `PORTING_NOTES.md` by the integrator.
Base: `8a773a7` (WP-4-5 accepted, D-283). Branch `claude/wp-4-6-client-cli`.

## Scope outside the brief (X-WP46-1)

The master's task monitor is shared with the recommendation pipeline (commit `50ea20b`).
Go's standalone `updateRecommend` passes `m.tracer` to the pipeline, so `ps` lists
`master Generate recommendation`. The Rust master gave the pipeline a monitor of its own, so that
line never reached the master's list. `TestPS` (`cli_ps`) cannot pass without it.

The change is `Arc<Monitor>` in `gorse-master` (`master.rs`, `tasks/recommend.rs`) and
`gorse-worker` (`pipeline.rs`, `worker.rs`, `testing.rs`). The coordinator approved it on
2026-10-30 as a separate commit. It does not touch `gorse-master`'s `rest/` or `gorse-cmd/src/master.rs`.
Tests after the change: `gorse-common` 277 passed (8 ignored), `gorse-worker` 22 passed,
`gorse-master` 48 passed.

## Deviations (D-WP46-n)

1. **Help and usage text is clap's, not cobra's.** `gorse-cli --help` and per-command help are not
   Go's text. The command tree and the names, flags and defaults match Go.
2. **Usage errors.** `unknown command "x" for "gorse-cli ..."` and `accepts N arg(s), received M` are
   cobra's text. Other parse errors (for example an unknown flag) use clap's wording, not cobra's
   `unknown flag`. Exit status is 1, as Go's `fatal` gives.
3. **Keyring backend.** Contexts are stored with `keyring` 4.2.0 (v1 API), which uses the Secret
   Service on Linux. This container has no default store, so context commands cannot run here. The
   tests use `MemoryKeyring`. The `SystemKeyring` path is not exercised by any test in this WP (open, O-WP46-1).
4. **`ps` lists the pipeline's task under `master`** (X-WP46-1), not under a tracer of the pipeline's own.
5. **Sort stability.** `recommend` and `get` sort by timestamp. For equal timestamps with 12 or more
   rows, the order can differ from Go's `sort.Slice`, which is not stable.
6. **json-patch errors.** `pipeline patch` uses `json-patch` 4.2.0. Its error texts differ from
   `evanphx/json-patch`. The success path matches the Go test.
7. **YAML.** `pipeline get` and `pipeline schema` write yaml.v3's layout: four-space indent, sorted
   keys, `%g` numbers, and quoting where yaml.v3 quotes. Literal blocks (`|`) are not written; such
   strings are double quoted instead.
8. **Test harness serializes setup.** Suites in `tests/gorse_cli.rs` and `gorse-client/tests/admin.rs`
   pick ports and bind them later, so parallel setup raced for a port (`AddrInUse`, seen once). A
   static async lock now serializes setup, as Go's serial suite does, and the HTTP listener is bound
   up front and kept.

## Go quirks reproduced (Q-WP46-n)

1. `get feedback click` (a stray word after the sub-command) is `unknown command "click"` (Go's cobra
   text), tested in `gorse_cli.rs`.
2. `pipeline set ...` is `unknown command "set"`, tested the same way.
3. `restore` prints one line after the `Confirm [y/N]` prompt, so its output has one newline. Tested.
4. `recommend item-to-item` and `user-to-user` take two words, which dispatch reads from one `args`
   argument. A debug assertion in clap rejected two arguments with the same id; they are one now.

## Harness changes (conformance)

- `GO_PACKAGES` builds `./cmd/gorse-cli` with the other Go nodes.
- `GoBuild::binary` is public, so tests can run the Go CLI.
- `gorse-client` and `regex` are dev-dependencies of `gorse-conformance` (`tests/mixed_cli.rs`).

## Mixed-CLI coverage (`conformance/tests/mixed_cli.rs`)

The two pairings run the same nine commands and check the same expected output:
`get categories`, `get user`, `get users`, `get item`, `get items`, `get feedback`, `stats`,
`pipeline get`, `pipeline schema`. Each pairing is one cluster, seeded as `SetupTest` does, after the
master's first `Load Dataset` completes.

The mixed run leaves out the recommendation commands, `ps`, `cluster-info`, `dump` and `restore`.
They need a master that has run recommendations or has a registered node, and the in-process
`gorse_cli.rs` covers them. `pipeline get` and `pipeline schema` are checked as text in the mixed
run. The in-process test parses the YAML with `yaml-rust2`.

## Open items (O-WP46-n)

1. **Keyring store.** `SystemKeyring` against a real Secret Service is untested. This container has none.
2. **Help text.** cobra's help and usage text is not reproduced (deviation 1).
3. **Backend acceptance.** Backend URIs are not set here (no Docker). The integrator runs the backend
