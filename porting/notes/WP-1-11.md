## Decisions

- **D-WP111N-1 Operand order of `+` and `*` on NaN (WP-1-3 `floats.rs`).** Go
  computes `dst[i] += c` as `ADDSS X0, X1`, with the destination element first
  (`go tool objdump` of the golden tool, `Feature.addConst`, `floats.go:126`).
  `Feature.mulConstAdd` (`floats.go:156`) computes `(a[i] * c) + dst[i]` as
  `MULSS X0, X1` followed by `ADDSS 0(SI)(AX*4), X1`. When both operands are
  NaN, x86 SSE returns the NaN of the first source operand (Intel SDM vol. 1,
  table 4-7), and LLVM may swap the operands of `+` and `*`. The change adds
  `add_first`, `mul_first` and `first_nan` (`floats.rs`). Each operation the
  Go code performs with the destination first now goes through them: the native
  kernels (`add`, `add_to`, `add_const`, `mul_to`, `mul_const_add`,
  `mul_add_to`, `dot`, `euclidean`, the scalar `mm`) and the public `add` and
  `mul_add_to`. The release golden is the test (see Evidence).
- **D-WP111N-2 `Exp` in `nn::deps`.** `deps::exp` calls WP-1-4's
  `util::rand::math::exp_with`, with the FMA choice from `Feature::current()`,
  which honours `GODEBUG` as Go's `internal/cpu` does. `util::rand::math` itself
  was a copy here until this part; `util::rand` now exposes `math` to the crate
  (`pub(crate) mod math`). See O-WP111N-2.
- **D-WP111N-3 Go's top-level `rand` in `nn::deps::global`.** Used where Go calls
  `rand.NormFloat64` and `rand.Perm` without a generator (`TestSaveAndLoad`'s
  spiral, and `rand(None, ..)` and `normal_init(None, ..)`). Go seeds that source
  randomly, so no test depends on its values, and nothing else uses it.

## Quirks reproduced

- **Q-WP111N-1 Shape checks.** `add`, `sub`, `mul`, `div` and `pow` require
  the second shape to be a suffix of the first, with Go's messages
  (`functions.rs`). `TestTensor_*` and `nn_go_*` cover the messages.
- **Q-WP111N-2 Reads past the end.** `embedding` and `slice_indices` read past
  the end of a slice where Go's unchecked index does (`nn.rs` module docs).
- **Q-WP111N-3 Shared data.** `slice`, `flatten` and `reshape` share their data
  with the source, so writes through one show through the others (`Tensor` docs).
- **Q-WP111N-4 `Load` panics.** Where Go panics while loading a model, `load`
  returns `Error::Panic` with Go's message (`layers.rs`, around lines 451-474).
- **Q-WP111N-5 Go's runtime messages** for index and slice bounds (`golang.rs`,
  tested by `nn_go_bounds_messages`).

## Deviations

- **X-WP111N-1 `add` of a tensor without elements.** Go loops forever (`i += 0`).
  The port panics with a message saying so (`tensor.rs`, `add`).
- **X-WP111N-2 Benchmarks not ported.** `tensor_test.go`'s `matMulLegacy`,
  `batchMatMulLegacy` and the `Benchmark*` functions measure speed and assert
  nothing, so they are not ported.
- **X-WP111N-3 Progress bar.** `TestMNIST`'s progress bar is not ported. The
  per-epoch line and the test accuracy are printed.
- **X-WP111N-4 Go's top-level `rand` is a stand-in** (D-WP111N-3): splitmix64
  with a random seed, and Box-Muller for `NormFloat64` rather than Go's ziggurat.
  Same distribution, different values, and Go's values are random too.
- **X-WP111N-5 Dataset tests ignored.** `TestIris` and `TestMNIST` need files
  from `cdn.gorse.io`, which is blocked (O-1). They are `#[ignore]` as `ann`'s
  are, and read `~/.gorse/dataset/{iris,mnist}`. `TestMNIST` also skips in Go
  unless on Apple silicon or AVX-512. The Rust test does not repeat that check.

## For the integrator

- **Review D-WP111N-1** (`floats.rs`, WP-1-3's file). Run
  `cargo test --release -p gorse-common --test floats_golden` as well as the
  debug run. The debug run cannot tell the fix from its absence.
- **Parallel calls (O-WP111N-1).** Go's four `parallel.For` calls (`tensor.go`
  566-593) are one Rust call: `deps::parallel_for` in `batch_mat_mul`
  (`tensor.rs`, near line 667). When WP-1-6 merges, replace it with
  `gorse_common::parallel::for_` and delete `deps::parallel_for`. Go's

  `tensor::run_parts`, which stays.
- **`util::rand::math` visibility.** `util/rand.rs` changed `mod math;` to
  `pub(crate) mod math;` so `nn::deps` can call `exp_with`. That is the only
  change to WP-1-4's files.

## Open

- **O-WP111N-1 `parallel.For` stand-in.** `deps::parallel_for` (see For the
  integrator) stays until WP-1-6 is on the integration branch.
- **O-WP111N-2 `GODEBUG` and `util::rand::math`.** `util::rand::math::use_fma`
  reads the CPU directly, without `GODEBUG`. Go's `math.Exp` takes the FMA path
  only when `internal/cpu` allows it, and `GODEBUG=cpu.avx=off` or
  `cpu.fma=off` turns it off. So WP-1-4's `NormFloat64` and `ExpFloat64` differ
  from Go under those `GODEBUG` settings, and `nn::deps::exp` does not.
  Owner: WP-1-4. Fix: make `use_fma` use `Feature::current()`, as `nn` does.
- **O-WP111N-3 Dataset tests** (X-WP111N-5) run once `cdn.gorse.io` is reachable,
  and need `iris.data`, `train.libfm` and `test.libfm` under
  `~/.gorse/dataset/`.
