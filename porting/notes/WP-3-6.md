## Spike: the `expr-lang` 2.1.0 crate (D-WP36-1)

Brief step 2 (crate-selection.md, row expr-lang/expr): evaluate `expr-lang` 2.1.0 against the
Go oracle corpus and keep it only if it passes. It does not. Scratch project outside the repo.
Corpus: `crates/gorse-expr/testdata/corpus/` (1330 cases, golden from expr-lang v1.17.8).

| Verdict over the 1327 non-volatile cases | Count |
|---|---|
| both reject, compile error | 391 |
| both reject, runtime error | 77 |
| values agree | 652 |
| values differ (int vs float from JSON, Go type names) | 166 |
| spike rejects where Go gives a value (`item.Timestamp.Unix()`, `now() - time`) | 27 |
| spike accepts where Go rejects at compile time (`1 == 'a'`, `nil?.a`, `$env[...]`) | 12 |
| spike returns nil where Go gives an index-out-of-range error | 6 |
| spike panics on valid Go syntax (`map {'b': 2}`) | 2 |

Reasons it is rejected: (1) no static type checking, which Gorse needs (`Node().Type().Kind()`
must be numeric for a score and bool for a filter, `non_personalized.go`); (2) error texts
differ from Go's `file.Error` format; (3) no Go `time.Time` and `time.Duration` semantics on
values built from Go structs; (4) panics on valid input; (5) no `;` sequences.
So the checker, compiler and VM are a hand port (D-10), in `gorse-expr`.

## Gate for the golden corpus

`contracts/tools/exprevalgolden` runs `expr.Compile` and `expr.Run` in the four environments
Gorse uses (`non_personalized`, `item`, `user`, `none`). `contracts/tools/exprcorpus/extract.py`
builds `expressions.json` from the Go tests, configs, the expr-lang docs (`expr` blocks) and
synthetic cases. Calls to `now()` that return a time or duration are volatile.

Found by the oracle: `Compile` runs the optimizer by default (`conf.CreateNew`, `Optimize: true`),
so `1 % 0` fails at compile time with "integer divide by zero". The port needs constant folding
with the same errors.
