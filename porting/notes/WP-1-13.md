# WP-1-13 notes: lafikl/consistent

Provisional ids; the integrator renumbers them into `PORTING_NOTES.md` and
`PORTING.md`. The Rust module is `crates/gorse-common/src/consistent.rs`,
porting `github.com/lafikl/consistent` at the version Gorse's `go.mod` pins
(`v0.0.0-20220512074542-bdd3606bfc3e`). The Go oracle data is
`crates/gorse-common/tests/data/consistent_golden.json`, written by
`contracts/tools/consistentgolden`, which reads (and, for the injected cases,
writes) the ring's unexported fields with `reflect`.

What Gorse depends on, the placement of users on workers, matches
`contracts/grpc.md` as written: 10 points per host at
`hash(host + decimal(i))`, a key owned by the first point `>= hash(key)`,
wrapping to the first point, `hash` the first 8 bytes of BLAKE2b-512 read
little-endian. The golden data checks it on 14 rings (1 to 10 worker uuids
made as `worker.go` makes them, adds, duplicate adds, removes, re-adds) for
2816 keys, including keys that hash exactly onto a point.

## Quirks reproduced

- **Q-WP113-1 A 64-bit hash collision leaves a point without a host.** `Add`
  overwrites the colliding point's host (last added wins) while the sorted set
  keeps both copies; removing either host deletes the shared map entry and one
  copy. `Get` landing on the orphaned point returns `""` and `GetLeast` panics
  (Go: nil pointer dereference in `loadOK`). Reproduced; checked against Go on
  states written straight into the fields (golden `injected`), since the real
  hash cannot be made to collide.
- **Q-WP113-2 `GetLeast` wraps at the number of distinct points**
  (`len(c.hosts)`), not the length of the sorted set; they differ only after a
  collision, when the last point is skipped. Reproduced; golden `injected`
  case `GetLeast wraps at the number of distinct points`.
- **Q-WP113-3 Reads that write the total load.** `MaxLoad` turns a total load
  of 0 into 1, and `loadOK` (inside `GetLeast`) turns a negative total into 0,
  both for good and both under Go's read lock (a data race in Go). Reproduced:
  `max_load` and `get_least` take `&mut self`; golden case `side effects on
  the total load` and the random sequences check the total after every call.
- **Q-WP113-4 `Remove` keeps the removed host's load in the total** and always
  returns `true`, also for a host that was never added. Reproduced.
- **Q-WP113-5 `MaxLoad` on an empty ring panics** (integer divide by zero),
  after setting the total to 1. Reproduced (golden `empty ring`).
- **Q-WP113-6 `Inc`, `Done` and `UpdateLoad` ignore unknown hosts**, and
  `Done` drives a load below zero. Reproduced. Load arithmetic wraps on
  overflow as Go's `int64` does (`wrapping_add`).

## Deviations

- **X-WP113-1 No internal lock.** Go's `Consistent` embeds a `sync.RWMutex`
  (so `Lock`/`RLock` are part of its exported API) and locks inside every
  method. The Rust ring takes `&mut self` to change and a caller that shares
  one wraps it in a lock. Gorse builds a fresh ring for each `pullUsers` call
  and uses it from one goroutine.
- **X-WP113-2 The exported `Host` struct is not a public type.** Loads are kept
  as host name to `i64`; `get_loads` returns the same map Go's `GetLoads`
  does. No Gorse code uses `Host`.
- **X-WP113-3 Panic texts differ.** Where Go panics with a runtime error
  (`integer divide by zero`, `nil pointer dereference`), Rust panics with its
  own text; the golden tests check that both panic at the same call.
- **X-WP113-4 Float-to-int conversion out of range.** `MaxLoad` converts
  `ceil(total / hosts * 1.25)` to `int64`; above `i64::MAX` (a total load over
  about 7.4e18) Go gives `i64::MIN` on amd64 and saturates on arm64. Rust
  saturates, as Go on arm64. Unreachable in practice.
- **X-WP113-5 Keys and hosts are `&str`.** Go strings may hold invalid UTF-8;
  worker uuids are hex and user ids are UTF-8 in every Gorse store.
