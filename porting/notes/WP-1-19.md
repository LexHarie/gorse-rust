## Decisions

- **D-WP119-1 The input is `&str`.** A Go string may hold any bytes; Gorse's
  `item_expr` values come from TOML (UTF-8 by its spec) and the
  `RECOMMEND_CONFIG` JSON override in the meta store (`master.go:164`, decoded
  to UTF-8); no environment binding sets one (`config.go:742-797`). So text is
  enough. The
  corpus inputs that are not UTF-8 cannot be passed and are counted per source
  in the golden files (two: one row of `TestLex`, one string literal of
  another expr-lang test).
- **D-WP119-2 Token values and `StringNode` values are bytes (`Vec<u8>`).**
  Go strings are bytes, and an escape can make a string literal's value
  invalid UTF-8 (Q-WP119-1). `Token::value_str` gives the text where it is
  UTF-8; identifiers and operators always are.
- **D-WP119-3 `parse` returns `Result<Tree, Error>`.** Go returns the
  half-built tree together with the error; every caller (Gorse's validator,
  `expr.Compile`, `expr.Eval`) drops it, so here the error is all there is.
  The parser keeps Go's control flow after an error exactly (it decides which
  error is reported, Q-WP119-2); a `None` child always comes with an error,
  so no node with a missing child is ever built.
- **D-WP119-4 Shared subtrees are cloned.** Go points the condition and the
  first branch of `a ?: b` at one node, and neighbouring comparisons of a
  chain `a < b < c` at one middle node (Q-WP119-11). A Rust tree owns its
  nodes, so these are equal copies. For WP-3-6: Go's checker and patchers
  visit such a node twice through the same pointer; with copies each is
  visited once, which gives the same result as long as visiting is
  deterministic.
- **D-WP119-5 Any depth, like Go.** Go's stacks grow to 1 GB, and a config
  may turn the node budget off (`MaxNodes: 0`), so depth is unbounded. The
  recursive functions (parser, printer, dump, walk, clone, compare, debug)
  run under `stacker::maybe_grow` (`stacker` 0.1.25, recorded in
  `porting/crate-selection.md`), and dropping a tree iterates.
  `tests/parser_deep.rs` parses, prints, walks, clones and compares trees
  100,000 levels deep on a 256 KiB thread; the synthetic goldens include
  200,000 nested parentheses and node chains on both sides of the budget.
- **D-WP119-6 What waits for WP-3-6.** `ConstantNode` (only the optimizer
  makes it; `TestPrint_ConstantNode` is not ported), the `nature`/type of each
  node and the `Node` interface's type methods, the rest of `conf.Config`
  (environment types, function values, builtins table, optimizer and VM
  switches), `file.Error.Prev` and the JSON tags of `file.Error`. The parser
  needs of `conf.Config` only `MaxNodes`, `Disabled`, `DisableIfOperator` and
  `IsOverridden`; the Rust `Config` holds the names of the functions and of
  the environment's entries as sets. Go's `IsOverridden` asks
  `Env.Get(name)` of the environment's nature; WP-3-6 derives the set from
  the environment's type.
- **D-WP119-7 The API is `parser::parse`, `parser::parse_with_config`,
  `parser::lexer::lex` and `Lexer::new(&Source)`.** Go's reusable `Parser`
  (with a `Parse` method) and `Lexer.Reset` are not ported (Q-WP119-9); one
  lexer per source.
- **D-WP119-8 Character classes come from Go's tables.** `unicode.IsLetter`,
  `IsDigit`, `IsSpace` and `strconv.IsPrint` are generated from Go 1.27.0
  (Unicode 17.0.0) into `unicode_tables.rs`, so the lexer and the quoting of
  error messages follow Go's Unicode version rather than Rust's. A unit test
  compares all four with Go for every code point.
- **D-WP119-9 The Go test tables are read from the Go source.**
  `exprparsegolden` (tables.go) turns the tables of `TestParse`,
  `TestParse_error`, `TestParse_optional_chaining`, `TestNodeBudget`,
  `TestLex` and `TestPrint` into `parser_go_tests.json` (expected trees as
  JSON, unset fields left to Go's zero values), and
  `tests/parser_go_tests.rs` runs them with Go's assertions (`Dump(want) ==
  Dump(actual)`, the error text, `compareTokens`, `Node.String()`).
  Hand-ported: `TestParse_pipe_operator`, `TestNodeBudgetDisabled`,
  `TestLex_location`, `TestLex_error` (its table is a constant, split as Go
  splits it), `TestPrint_MemberNode`, `ast` `TestWalk`, `TestWalk_patch`,
  `TestFind`, and `file` `TestStringSource_Snippet*`.
- **D-WP119-10 Licence.** The crate ports MIT-licensed code: `license =
  "Apache-2.0 AND MIT"`, with expr-lang's licence in
  `crates/gorse-expr/LICENSE-expr-lang`.

## Quirks reproduced

Each is in the golden data (`quirks` source of `parser_golden.json` unless
said otherwise), so the Rust result is Go's.

- **Q-WP119-1 `\U` escapes wrap Go's 32-bit runes.** The unescaper shifts
  eight hex digits into an `int32`; from `\U80000000` up the value is
  negative, passes the `> MaxRune` check and is written as its low byte:
  `"\UFFFFFFFF"` is the one byte `0xFF` (printed `"\xff"`), `"\U80000041"` is
  `"A"`. `\U7FFFFFFF` and `\U00110000` fail ("unable to unescape string").
  Surrogates (`"\uD800"`, `"\u{D800}"`) become U+FFFD.
- **Q-WP119-2 A lexer error replaces an earlier parser error.** The lexer
  runs lazily, one token ahead of the parser; the parser's own errors are
  first-wins, but a lexer error met while the parser keeps reading after its
  error overwrites it. `count(, 1)` fails with `unexpected token
  Operator(",") (1:7)`, `count(,"\q")` with `invalid char escape (1:10)`.
- **Q-WP119-3 The `if` form's node is not counted and has no location.**
  `parseConditionalIf` builds the `ConditionalNode` directly instead of
  through `createNode`: it is outside the node budget and its location is
  `0:0` (`if a { 1 } else { 2 }` walks to `ConditionalNode 0:0`).
- **Q-WP119-4 `true`, `false`, `nil` and numbers take no postfix.** They
  return before `parsePostfixExpression`: `true.foo` is `unexpected token
  Operator(".")`, `nil[0]` likewise, and `1.foo` is `bad number syntax:
  "1.f"` (the lexer reads `1.` as a number).
- **Q-WP119-5 Map pairs are at the `{`.** Every `PairNode` takes the
  location of the map's opening brace, not of its key.
- **Q-WP119-6 A ternary is at the token after it.** The `?:`
  `ConditionalNode` takes the location of the current token after its second
  branch (for `a ? b : c`, the end of input, `8:9`).
- **Q-WP119-7 `not` before an operator is matched by value and located at the
  operator.** After `not` the parser checks only the next token's value, so a
  string `"in"` works as the operator: `a not "in" b` is `not (a in b)`. The
  `UnaryNode` takes the location of the `in` token, not of `not`.
- **Q-WP119-8 The lexer and the unescaper disagree on escapes.** The lexer
  rejects `\?`, `` \` `` and an escaped quote of the other kind (`'\"'`:
  `invalid char escape`), which the unescaper would accept; it accepts octal
  escapes from `\4` to `\7`, which the unescaper rejects (`"\400"`:
  `unable to unescape string`).
- **Q-WP119-9 Go's `Lexer.Reset` keeps the previous positions.** Reusing a
  lexer (or a `parser.Parser`) for a second source starts reading at the
  first one's end. `parser.Parse` and `ParseWithConfig` make a new parser each
  time, so Gorse never sees it; the port has no reuse API (D-WP119-7).
- **Q-WP119-10 Newlines.** A quoted string cannot hold a line feed (`literal
  not terminated`), but a lone carriage return in it becomes a line feed;
  backquoted strings keep `\r` as is.
- **Q-WP119-11 Comparison chains and `?:` share operands.** `a < b < c <= d`
  is `a < b && b < c && c <= d`; `a ?: b` is `a ? a : b` (D-WP119-4).
- **Q-WP119-12 An error on an empty line has no position.** `file.Error`
  leaves the snippet empty when the error's line is empty, and then prints
  only the message: `a +\n\n` fails with just `unexpected token EOF`.
- **Q-WP119-13 Numbers.** Underscores are removed anywhere before parsing
  (`0x_1` is 1, `1_0` is 10); decimal literals may have leading zeros (`08`
  is 8); the most negative integer cannot be written (`-9223372036854775808`
  is unary minus on an out-of-range literal); a float that overflows is
  `invalid float literal: ... value out of range`, one that underflows is 0.
  The parser's `float literal is too large` and `integer literal is too
  large` checks cannot fire on 64-bit Go.
- **Q-WP119-14 Disabling a builtin does not touch the predicate builtins.**
  `Disabled` applies to the builtins table only; `all`, `count`, `map`,
  `filter` and the other predicate functions are still parsed as builtins
  (golden config 7). Functions and environment names override both
  (configs 8 and 9).

## Evidence

- Go oracle: `parser_golden.json` (746 curated cases in full: error or dump,
  printed tree and walk with locations, plus the lexer's tokens; 6,853 config
  cases over 11 configs; 30 synthetic inputs; 4,473 quoting cases; the four
  Unicode classes), `parser_bulk_golden.json` (95,585 inputs from 9 sources
  with verdict and digest), `parser_go_tests.json` (the Go test tables). All
  match.
- Mutation checks: 38 deliberate bugs, one per quirk or rule above (budget
  off by one, if-node counted, pair/ternary/not locations, `\U` not wrapping,
  lone CR kept, postfix after literals, lexer error not replacing the
  parser's, queued tokens before a lexer error, operator tokens, character
  classes, quoting, number parsing, disabled/overridden builtins, ...); the
  acceptance command fails on all 38 (list in the commit message).
