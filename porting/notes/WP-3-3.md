# WP-3-3 notes: hyper-parameter tuning (provisional ids)

Source: c-bata/goptuna v0.9.0 (the version root `go.mod` pins), `model/cf/optimize.go`,
`model/ctr/optimize.go`, the `SuggestParams` methods, and Go's `math` package (go1.27.0)
for `Erf`, `Max` and `Min`. The integrator folds these into PORTING.md and PORTING_NOTES.md.

## Ported

- `crates/gorse-model/src/tpe.rs` and `tpe/`: the TPE sampler (`sampler.rs`), its Parzen
  estimator (`parzen.rs`), the distributions (`distribution.rs`), the random sampler and
  multinomial draw (`random.rs`), and `Erf`, `Max`, `Min` (`gomath.rs`). `Study`, `Trial`,
  `Direction`, `TrialState`, `FrozenTrial` and the errors are in `tpe.rs`.
- `crates/gorse-model/src/cf/optimize.rs` and `ctr/optimize.rs`: `ModelSearch` with
  `objective`, `result`, `with_context`, `with_span`. Go's `NewModelSearch` takes a map of
  model types; the Rust port takes a `BTreeMap`, so the categorical choice is over sorted names.
- `SuggestParams` for BPR and ALS (`cf/model.rs`, Go lines 397 and 588) and AFM
  (`ctr/fm.rs`, Go `model/ctr/fm.go` line 79).
- Contracts touched (both approved by the coordinator on 2026-10-28):
  - `gorse-common`: `util::rand` is `pub mod math`, and `math::{exp, log}` are `pub` with docs.
  - `gorse-model-core`: `SuggestTrial` trait, and `Model::suggest_params(&self, &mut dyn SuggestTrial) -> Params`.

## Go oracle

- `contracts/tools/tpegolden` writes `crates/gorse-model/testdata/tpe/golden.json`:
  `math.Erf` over 769 points, `math.Max`/`math.Min` over 64 pairs of special values, and a
  60-trial goptuna study with `SamplerOptionSeed(1)` over every distribution.
- `tpe::golden` compares them bit for bit (a NaN matches any NaN, since Go's NaN has a
  different payload). Replay maximum difference: 0. The three golden tests pass.
- The generator needs `GODEBUG=randautoseed=0`. Without it the output changes between runs.
  Documented in `contracts/README.md`.

## Deviations (provisional)

- D-WP33-1: `gonum`'s `floats.Argsort` sorts its input in place. goptuna's
  `NewParzenEstimator` relies on that, so the `mus` slice it is given comes back sorted.
  The Rust port keeps the in-place sort (`parzen.rs`, `argsort`) rather than sorting a copy.
  Recorded as Q-WP33-1.
- D-WP33-2: `gonum`'s `floats.Sum` and `CumSum` on amd64 use SIMD, and their summation
  order depends on memory alignment. The port sums sequentially. Recorded as X-WP33-1.
- D-WP33-3: goptuna's `multinomial` and categorical draws read math/rand's global source,
  which Go seeds from the runtime (or with 1 under `GODEBUG=randautoseed=0`). Rust has no
  process-wide source with those semantics, so each `TpeSampler` and `RandomSampler` owns a
  global source seeded from `RandomState`. The golden test seeds it with 1. Recorded as X-WP33-2.
- X-WP33-3: `Erf` is ported locally from `math/erf.go`, and `Max`/`Min` from `math.go`,
  because Rust's `f64` methods differ on NaN and signed zero. Approved in the coordinator's ruling.
- X-WP33-4: the module headers name `c-bata/goptuna@v0.9.0` and `go1.27.0`, not the
  add21b5 gorse pin, because the sources are goptuna and the Go standard library.
- X-WP33-5 (X-65): the tuning hook is `SuggestTrial` in model-core, not goptuna's `Trial`
  type. Approved by the coordinator.
- Q-WP33-2: Go's `ModelSearch` takes model types from a map, whose iteration order is random.
  The port uses name order, so the trial sequence is fixed for a given seed.
