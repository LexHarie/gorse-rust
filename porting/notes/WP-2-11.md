# WP-2-11 notes (meta store). Provisional ids; the integrator folds them and deletes this file.

Ports: `storage/meta/database.go`, `sqlite.go`, `database_test.go`,
`sqlite_test.go` @ add21b5. Code: `crates/gorse-storage/src/meta/`. Golden
generator: `contracts/tools/metagolden`, data `crates/gorse-storage/tests/data/meta_golden.json`
(go1.27.0).

## Decisions

- **D-WP211-1. The meta traits are async, `Open` is async.** D-122. `Database` is
  `#[async_trait]` (dyn-compatible, since `Open` returns one), with no `ctx`
  because Go's `meta.Database` takes none. Every method runs on
  `tokio::task::spawn_blocking` (`porting/crate-selection.md`, rusqlite row).
- **D-WP211-2. SQLite is `rusqlite` (bundled), not `sqlx`.** The crate-selection
  row for gorm sqlite. The store has one connection behind a std `Mutex` that
  only blocking tasks lock.
- **D-WP211-3. The time text is Go's.** modernc writes `t.String()` of the UTC
  time (`conn.go` `formatTime`, default `writeTimeFormat` is empty) and reads the
  `String()` layout, with an optional `m=` suffix, then its seven layouts
  (`conn.go` `parseTime`). The port does the same, so Go and Rust rows in one
  file compare alike under `datetime('now', ...)`. Golden: `update_time_text_matches_go`,
  `update_time_is_stored_as_go_stores_it`, `go_written_rows_are_listed_and_pruned`.
- **D-WP211-4. `Node` and `Model` are plain structs.** `Node.Type` is `r#type`.
  `ListNodes` returns `Vec<Node>` (Go's `[]*Node`). `Model` JSON keeps Go's field
  names (`ID`, `Type`, `Params`, `Score`) through serde renames.
- **D-WP211-5. `FromJSON` merges `Params` into the map it holds.** This follows
  Go's `json.Unmarshal` into a map: keys the JSON names are replaced, the others
  stay, and `null` clears the map. Absent fields keep their values, and a `null`
  for `ID`, `Type` or `Score` is a no-op. Golden: `from_json_matches_go`.

## Deviations (X) and open questions (Q, O)

- **X-WP211-1. A nil `Params` encodes as `{}`, not `null`.** `Params` is a
  `BTreeMap`, which has no nil. Go writes `"Params":null` for a model with nil
  params (golden: `int_score`, `nil_params`). Both are read back the same by Go.
  The golden test checks this case explicitly (`NIL_PARAMS`), it is not skipped.
- **D-WP211-6. A decoded array or object is `ParamValue::Json`.** Resolves
  O-WP211-1 (coordinator decision, 2026-10-28 12:00Z). `FromJSON` keeps the
  `gojson::Value` of an array or object, so it encodes again as Go encodes the
  value: numbers as float64s, object keys sorted by bytes, the same escapes as
  `json.Marshal`. The accessors treat it as a type mismatch, as Go's do for a
  `[]any`. Golden: `round_trip_matches_go` (8 cases, Go's bytes), and
  `from_json_matches_go` compares the array values too.
- **X-WP211-3. `ToJSON` returns `Result`.** Go's `lo.Must1` panics. The
  error cases are a score that `encoding/json` refuses (a NaN) and
  `ParamValue::Other`, which Gorse never stores. Phase 4 callers decide what to
  do with the error.
- **X-WP211-4. `FromJSON` matches JSON keys case-sensitively.** Go's
  `json.Unmarshal` matches `"id"` to `ID` and `"type"` to `Type`. serde does not.
  Go's own writer always writes the exact names, so the rows of both
  implementations match.
- **X-WP211-5. A type mismatch stops the decode.** Go's `json.Unmarshal` keeps
  decoding the other fields and returns the first type error. The port stops
  at the first error, so a partly-set model can differ from Go's after an error.
- **X-WP211-6. Error texts are not Go's.** `encoding/json` texts (syntax, type
  errors) are serde's and gojson's. The `Scan` failure keeps Go's text
  (`Error::UnsupportedScan`). Only the error/no-error outcome is golden-checked.
- **X-WP211-7. `Open` connects now; Go's `sql.Open` connects on first use.** An
  unusable file fails at `Open` here, and at `Init` in Go. Both fail the same
  start-up path.
- **X-WP211-8. The DSN's query string is not parsed.** The file is the part
  before any `?`. The busy timeout (10 s) and WAL mode are set on the
  connection, as Go's `_pragma` parameters set them. No caller passes another
  parameter (`master.go:287` passes none).
- **X-WP211-9. One connection, not a pool.** Calls are serialised, where Go's
  `database/sql` pool can run them in parallel. Results match; the node has
  one meta writer, so nothing waits on the lock in practice.
- **Q-WP211-1. `Equal` does not panic on slice parameters.** Go's `maps.Equal`
  compares `any` values with `!=`, which panics when both sides hold the same
  uncomparable type (for example two `[]int`). The port returns a value and
  does not panic.
- **O-WP211-1. Resolved by D-WP211-6.** The coordinator approved a `ParamValue`
  variant that holds a JSON value (2026-10-28 12:00Z). The change is in
  `crates/gorse-model-core/src/params.rs` (`ParamValue::Json`), with one case
  added to `tests/params_go.rs` for the accessor mismatch.
- **O-WP211-2. Phase 3 must give `cf.Score` and `ctr.Score` Go's encoding.**
  `Model<T>` writes its `Score` with `jsonutil::marshal`, which matches Go for
  numbers and strings, and reads it with serde. A struct score needs serde
  renames that match Go's field names (Go has no tags here), and Go's
  encoding of a `float64` field must be checked against the golden data then.
- **O-WP211-3. Node JSON for the REST API is not defined here.** Go's `[]meta.Node` in
  `master/rest.go` is the REST shape. `Node` has no serde impl; Phase 4 adds it
  with Go's field names and RFC 3339 time text.
