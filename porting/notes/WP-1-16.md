## Decisions

- **D-WP116-1 Param value type.** `ParamValue` has one variant per Go dynamic
  type Gorse stores: `Nil`, `Int` (Go `int`, `i64`), `Int32`, `Int64`,
  `Float32`, `Float64`, `Bool`, `String`, `IntSlice` (`Vec<i64>`). The accessors
  switch on the variant, which keeps Q-15 (JSON gives `float64`, so `get_int`
  falls back to its default). `Other(&'static str)` stands for any other Go
  type, named as Go prints it. The Go test uses `[]string{"hello"}` as its wrong
  type, so the Rust test uses `Other("[]string")`. `gob::Value`
  (`gorse_common::encoding::gob`) was not reused: it has no `Other`, and it
  belongs to another crate. The gob
  codec for model blobs and the meta store (WP-2-11) convert to and from
  `ParamValue` where they read and write `Params`.
- **D-WP116-2 Names.** Go's `ParamName` is a string type. Here names are `&str`
  arguments, `String` map keys, and the predefined names are `&str` constants
  with SCREAMING_SNAKE names (`N_EPOCHS` for `NEpochs`). Entries are in a
  `BTreeMap`, so iteration is by name.
- **D-WP116-3 Copy.** Go's `Params.Copy` is `Clone` here. `Overwrite` returns a
  new map and takes `&Params`.
- **D-WP116-4 Random generator.** `BaseModel` stores
  `Option<RandomGenerator>`, so `BaseModel` has `Default`. `SetParams` seeds it
  from `RandomState` (0 when missing or not an `int64`), as Go does.
- **D-WP116-5 Downloads.** The download uses a `reqwest` blocking client with
  its timeout turned off. Go's `http.Get` has no timeout, and reqwest's blocking
  client gives up after 30 seconds (`reqwest` 0.13.5,
  `src/blocking/client.rs`, `Timeout::default`).
- **D-WP116-6 Home directory.** `gorse_dir`, `dataset_dir` and `temp_dir` are
  functions that read `$HOME` on each call (X-55). Go computes them once in
  `init`. Tests use `locate_built_in_dataset_in` and `create_dirs` with
  temporary directories, because setting `$HOME` in a test is `unsafe` in
  edition 2024 and the workspace denies `unsafe`.

## Deviations

- **X-WP116-1 `SuggestParams` is not in the `Model` trait.** Go's
  `SuggestParams(trial goptuna.Trial) Params` needs goptuna's `Trial`, which is
  part of the tuning port (WP-3-3, `model/cf/optimize.go` and
  `model/ctr/optimize.go`). WP-3-3 adds it to the trait, and the models implement
  it there. The other `Model` methods are here.
- **X-WP116-2 `init` side effect.** Go's `init` creates `~/.gorse/dataset` and
  `~/.gorse/temp` when any binary starts, and stops the process if that fails.
  The Rust library creates nothing on load. `create_built_in_dirs` does the
  same work and returns the error. The binaries (WP-4-7) call it at startup.
  `locate_built_in_dataset` makes the directories it writes into, as Go's
  download path does.
- **X-WP116-3 File permissions on unzip.** Unzipped files get default
  permissions, not `f.Mode()`. Same as X-56 for `datautil`.
- **X-WP116-4 `GetRandomGenerator` before `SetParams`.** Go returns a zero
  generator that panics on first use. Here the getter panics. No caller
  reaches it before `SetParams`, since every model calls `SetParams` in its
  constructor (WP-3-*).
- **X-WP116-5 `Copy` does not share slices.** Go's `Copy` is shallow, so an
  `IntSlice` value is shared between the copies. `GetIntSlice` has no caller
  in the Go tree (only its definition), so the sharing is not reachable.
- **X-WP116-6 `unzip` returns only the error.** Go returns the names it wrote
  before an error, together with the error. No caller reads those names, so
  `unzip` returns the error alone.

## Quirks reproduced

- **Q-WP116-1 `GetString` panics on any other type.** Go's `val.(string)` panics
  with `interface conversion: interface {} is float64, not string`. The Rust
  `get_string` panics with the same text (it does not log and return the
  default as the other getters do). Test:
  `get_string_panics_on_another_type_as_go_does`.
- **Q-WP116-2 The download keeps any body.** `http.Get` does not check the
  status, so an HTTP 404 page is saved as the zip. Here no status check is made.
  Test: `download_saves_the_body_of_an_error_status`.
- **Q-WP116-3 A failed download reports the unzip error.**
  `LocateBuiltInDataset` ignores the download's error. The file is left empty,
  and the unzip then fails. Here the same. Test:
  `failed_download_leaves_an_empty_file_and_returns_its_path`.
- **Q-WP116-4 Only a missing file downloads.** `os.IsNotExist(err)` on the
  training file is the only trigger. Any other stat error returns the paths with
  no download. Here `fs::metadata` with `ErrorKind::NotFound`.
- **Q-WP116-5 The format error.** The message is `format not matchs %v != %v`
  (the typo is Go's), and `%v` prints the `iota` numbers: `format not matchs
  0 != 1`. Test: `locate_rejects_a_format_mismatch_with_go_s_message`.
- **Q-WP116-6 Absolute entry names stay inside the destination.** Go's
  `filepath.Join(dst, "/abs/x")` is `dst/abs/x`, so the entry is extracted
  there and the ZipSlip check passes. The Rust `unzip` strips the leading `/`
  before joining. Test: `unzip_writes_an_absolute_entry_name_under_the_destination`.
- **Q-WP116-7 `Params` type mismatch log.** Q-16 applies: the log names
  `ParamName`, not the value's type. Reproduced in `type_mismatch`.
- **Q-15 (JSON floats).** Reproduced through `ParamValue::Float64` and the
  exact-type `get_int`. Test: `get_int_does_not_accept_an_int64_or_a_float_from_json`.

## Cross-thread findings

- **WP-1-8 `datautil.rs` (merged at 25c5bb8) has the same 30 second timeout.**
  Its `download_from_url` calls `reqwest::blocking::get`, which builds a client
  with the default timeout (see D-WP116-5). The util thread owns that file and
  is told in its thread. Not changed here.

## Hand-offs

- WP-1-18 (dataset) uses `Params`, `ParamsGrid` and `locate_built_in_dataset`.
- WP-3-3 (tuning) adds `suggest_params` to the `Model` trait (X-WP116-1).
- WP-2-11 (meta) reads and writes `Params` as JSON. Numbers come back as
  `ParamValue::Float64` (Q-15).
- The gob codec for model blobs converts between `gob::Value` and
  `ParamValue`. Whichever WP first reads a `Params` blob owns that conversion.
