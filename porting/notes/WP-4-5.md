# WP-4-5 notes: binaries (`crates/gorse-cmd`)

Provisional ids, folded into `PORTING.md` and `PORTING_NOTES.md` by the integrator.
Base: integration head `9ed33cd`. Branch `claude/project-thread-02wq8p`.

## Deviations (D-WP45-n)

1. **Version banner (`version.rs`).** Go sets `Version`, `GitCommit` and `BuildTime` with `ldflags`.
   This port has no `ldflags`: `Version` is the crate's version, and the commit and build time keep
   Go's defaults. The `Go version:` line is left out, since the binary is not a Go build.
2. **Go's help text is reproduced as printed (`server.rs`).** Go's source gives `--http-host` the text
   of `--http-port` and the reverse. The port keeps Go's text, so `--help` matches the contract file.
3. **Flags use clap's builder API, not derive (`cli.rs`).** The `--cache-path` default is made when the
   command is built (Go's `config.MkDir` runs in `init`), and the help-file test reads the command's
   metadata. Defaults that are made at run time are leaked once per process, since clap keeps them
   `'static`.
4. **Usage errors exit 1, not clap's 2 (`cli.rs`).** Go's cobra prints the error and then
   `log.Fatal` exits 1. Help and version exit 0, as in Go.
5. **Integer flags are typed narrower than Go's `int`.** Ports are `u16`, and `--jobs` is `usize`.
   A port out of range, or a negative `--jobs`, is a usage error here. Go accepts them and fails later,
   at the listener or in the worker.
6. **`gorse-in-one --playground` restores after the stores open.** Go's `setup` imports the dump before
   `Serve` opens the stores again. Here `Serve` opens the stores first, the import runs, and then the
   HTTP listener starts. The scheduled tasks that `Serve` starts may run once before the import. The
   end state is the same; the first task run sees the data a moment later. Playground only; not
   exercised here (O-1).
7. **Playground output differs in two lines and loses the progress bar.** `Using N CPU cores` has no CPU
   brand name, since there is no `cpuid` crate in the port. The download progress bar is not printed.
8. **The master's HTTP listener is bound in `gorse-cmd` (`master.rs`).** Go's `Serve` ends with
   `StartHttpServer`, which blocks. WP-4-4 ported the router (`gorse_master::rest::router`), but no code
   bound the port. `gorse-cmd` binds it and adds `/apidocs.json` (the frozen `contracts/rest/master.openapi.json`)
   and `/metrics`. Go's `StartHttpServer` also registers the routes listed in X-WP45-1 below, which this port
   does not serve.
9. **`Master::restore` (`crates/gorse-master/src/rest/dump.rs`, its own commit `5b7f343`).** A pub
   wrapper over `restore_dump` with the delta argument. Coordinator-approved cross-crate touch (2026-10-29).
   It returns the error message, not the stats, since the playground does not print the stats.
10. **Stray words are accepted (`cli.rs`).** cobra accepts arguments on a root command with no
    subcommands and ignores them. A hidden positional takes them, so `gorse-master extra` runs.
11. **Harness additions (`conformance/src/cluster.rs`).** `RustBuild` builds `gorse-cmd`'s binaries
    with a nested `cargo build -p gorse-cmd --bins`, since cargo sets `CARGO_BIN_EXE_*` only for the
    package that owns a binary. `spawn` now calls `spawn_at`, with the same behaviour. New helpers:
    `start_rust_master_binary`, `start_rust_server_binary`, `start_rust_worker_binary`.

## Go quirks reproduced (Q-WP45-n)

1. The `--http-host` and `--http-port` help texts are swapped in Go's source (deviation 2).
2. `--playground` takes no separate value word, as pflag's `NoOptDefVal` does (`--playground ml-100k`
   runs the bare flag, and `ml-100k` is a stray word). Tested in `tests/binaries.rs`.
3. `-v` and `--help` still create `$HOME/.gorse/var/lib/master`, because `config.MkDir` runs in `init`.
   Tested in `tests/binaries.rs`.
4. `--cache-path` is defined on `gorse-server` and `gorse-worker`, and neither Go node reads it.
   The port keeps the flag and does not read it.
5. An SSL flag subset is fatal with `incomplete SSL configuration` (Go `main`). Tested for server and worker.
6. `gorse-in-one --playground` overwrites `$HOME/.gorse/etc/config.toml` on each start (Q-30 in
   `PORTING_NOTES.md`). The port does the same.

## Open items (X-WP45-n, O-WP45-n)

1. **Master HTTP routes not served (X-WP45-1).** Go's master also serves the Swagger UI page at
   `/apidocs`, the pprof handlers under `/debug/pprof/`, and a CORS filter that allows the configured
   `master.http_cors_domains` and `http_cors_methods`. The port serves none of these. The Rust server
   has the same gap for `/apidocs` and pprof. The CORS responses use `Access-Control-Allow-Origin: *`
   (WP-4-2, WP-4-4). Owner to be set by the integrator.
2. **Playground not run (O-1).** `tests/playground.rs` is `#[ignore = "O-1: dataset from cdn.gorse.io"]`.
   The host is blocked here.
3. **Stale comment in `crates/gorse-worker/src/worker.rs:74` (WP-4-1, report only).** `WorkerOptions::tls`
   says `Worker::serve` refuses TLS. The code builds a TLS channel (`master_channel`), and
   `mixed_worker` runs the mutual-TLS case. Not changed in this WP.
4. **Go's `Restore` stats are dropped in the playground.** Not printed by Go's `setup` either (see deviation 9).
