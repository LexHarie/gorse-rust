# WP-4-7 notes: the Go SDK suite against mixed clusters (`conformance/tests/mixed_cluster.rs`)

Provisional ids, folded into `PORTING.md` and `PORTING_NOTES.md` by the integrator.
Base: integration head `fce6442`. Branch `claude/wp-4-7-sdk-suite`.

## Deviations (D-WP47-n)

1. **The dump is read from the datasets archive, not downloaded (`mixed_cluster.rs`, `dump`).** The
   setup (`client/setup-test.sh`) runs `wget https://cdn.gorse.io/example/ml-100k.bin.gz` and then
   `gzip -d`. This environment blocks the CDN (O-1). The harness reads the same archive from
   `/mnt/project-files/datasets/ml-100k.bin.gz`, or from `GORSE_ML_100K_DUMP` when that is set, and
   decompresses it in process. The archive's sha256 starts `a867552b`, the same as the file in
   PORTING_NOTES O-1. The restore must report 943 users, 1,682 items and 100,000 feedback. No setup
   script is edited: `client/setup-test.sh` is unchanged.
2. **The SDK config is `client/config.toml`, not `contracts/config/config.toml`
   (`cluster.rs`, `Cluster::new_from_config`).** The setup starts gorse-in-one with that file, and its
   recommenders (`latest`) and ranker (`none`) are what the suite's expectations were written for.
   The run's stores, ports and blob directory still replace the file's values, as the setup's
   `GORSE_DATA_STORE`/`GORSE_CACHE_STORE` environment does. `Cluster::new` and `new_with_store` keep
   the contract config and their behaviour; `create` takes the base path as an argument.
3. **The master restarts after the restore (`cluster.rs`, `Cluster::stop_master`).** The setup runs
   `docker compose restart master`. The harness stops the master process and starts it again with the
   same flags, then waits for training.
4. **The harness waits for training, which the setup does not (`mixed_cluster.rs`, `wait_for_training`).**
   The setup's last wait greps the dashboard tasks for the name `Train Collaborative Filtering Model`,
   which can pass before training runs. The harness waits until that task is `Complete` and no task is
   `Running`, and fails at once if it is `Failed`. Measured on the Go baseline, training takes about
   seven seconds after the restart. `TestItemToItem` reads the trained model at query time.
5. **Worker interval and jobs are the worker defaults (`mixed_cluster.rs`).** `--interval 1m0s` and
   `--jobs 1`, the same as the setup, which passes no worker flags.
6. **The suite is run as `go test ./client -run ^TestGorseClientTestSuite$ -count=1 -json`** with
   `GORSE_SERVER_ENDPOINT` and `GORSE_DASHBOARD_ENDPOINT` set to the run's ports. This is the command
   of `.github/workflows/build_test.yml`. `-json` is parsed: every one of the six suite tests and the
   suite itself must report `pass`. A skip, a failure or a missing test fails the leg.
