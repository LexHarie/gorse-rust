# WP-2-6: SQL cache store

Ports `storage/cache/sql.go` and `sql_test.go` @ add21b5 to
`crates/gorse-storage/src/cache/sql.rs`, with the shared connection glue in
`crates/gorse-storage/src/sqlconn.rs`. Ids follow the integrator's fold:
D-167 to D-175, Q-229 to Q-232, X-138 to X-145.

## Decisions

- **D-167 Drivers.** MySQL and Postgres run on `sqlx` 0.9.0 with explicit SQL
  per dialect. SQLite runs on `rusqlite` on `tokio`'s blocking pool, behind
  `Arc<Mutex<Option<Connection>>>`; the mutex is held only inside the blocking
  closure, never across an `.await`. The trait is the async D-122 trait.
- **D-168 rusqlite is 0.39.0, not the latest 0.41.0.** `sqlx` 0.9.0 (the
  latest) resolves `sqlx-sqlite`, which needs `libsqlite3-sys` below 0.38. The
  `links = "sqlite3"` rule allows one `libsqlite3-sys` per graph, so `rusqlite`
  0.41 cannot resolve with it. This departs from the latest-versions rule for
  `rusqlite` only. Ruled by D-160 (integrator). After the merge of f74ce29b the
  `sqlite` feature is empty, since the meta store links `rusqlite` unconditionally.
- **D-169 SQL is written out per dialect.** The statements copy the ones GORM
  issues: `ON DUPLICATE KEY UPDATE ... VALUES()` on MySQL, `ON CONFLICT ... DO
  UPDATE SET ... excluded.x` on Postgres and SQLite, `JSON_CONTAINS` on MySQL and
  SQLite (a deterministic `json_contains` registered on each SQLite connection,
  Q-25), and `@>` on Postgres `text[]`.
- **D-170 Init is not GORM AutoMigrate.** Init runs `CREATE TABLE IF NOT
  EXISTS` for the three tables, and on MySQL `ALTER TABLE ... ADD INDEX`, ignoring
  duplicate-index error 1061 as Go does. MariaDB cannot index `CAST(... AS CHAR
  ARRAY)`, so that index is skipped there as in Go. Postgres adds `btree_gin` and a
  GIN index on `(collection, subset, categories)`. Column alterations that GORM
  would make on an existing table are not reproduced.
- **D-171 Categories.** A nil list writes NULL; an empty list writes `"[]"` on
  MySQL and SQLite and `'{}'` on Postgres. An empty patch writes `"[]"`.
- **D-172 Purge.** Purge deletes values and documents only. Time-series points
  survive, as in Go.
- **D-173 Pool.** `ApplySQLPool` sets the maximum open connections and the
  connection lifetime. Go's `MaxIdleConns` has no sqlx counterpart and is read and
  dropped. When no maximum is set, sqlx uses its default of 10; Go's default is
  unlimited.
- **D-174 Connection glue.** `sqlconn` holds the MySQL DSN parsing, the
  per-connection session variables, the pool options and `json_contains`. The SQL
  data store (WP-2-2) shares it; reconcile at merge if that store lands its own.
- **D-175 Async registry creators.** The integrator applied D-151 on integration
  (1a14f9c, D-157). The SQL creators use the async `Creator` and register in
  `cache::register_builtin`, which the merge commit wires.

## Quirks reproduced

- Categories are written with Go's `json.Marshal` escapes: `<`, `>`, `&`, U+2028
  and U+2029 become `<`, `>`, `&`, ` ` and ` `.
- SQLite timestamps are written as `time.Time.String()`, including the sub-second
  digits Go keeps.
- `Purge` keeps `time_series_points` (Go quirk, D-172).
- An empty `AddScores` returns nil without a query.

## Deviations and notes

- **X-138 DSN options with no effect.** Timeouts, `charset` and `loc` are
  parsed and ignored. Unknown parameters become session variables, as Go's driver
  does.
- **X-139 TLS.** `sqlx`'s default TLS differs from `lib/pq`'s
  `sslmode=require`. The DSN `tls` values map as follows: `""` and `false` mean
  disabled, `preferred` means preferred, `skip-verify` means required without
  verification, and `true` means verify identity. A registered TLS configuration
  is an error, not a silent plain connection.
- **X-140 Sub-microsecond timestamps.** Postgres rounds in `lib/pq`; `sqlx`
  truncates. Postgres numerics are bound as their shortest decimal text, as
  `lib/pq` does.
- **X-141 Buffered scans.** `scan` and `scan_scores` read all rows before the
  first callback, and check the context before each callback. Go streams rows.
- **X-142 NULL decodes to zero.** A NULL in a non-pointer column reads as the
  zero value, as Go's scan does.
- **X-143 One SQLite connection.** Go's pool of connections is one connection
  behind a mutex. Writes serialise; reads see the same data.
- **X-144 MySQL full authentication over plaintext (resolved, matches Go).** On a
  non-TLS connection, `caching_sha2_password` full authentication needs the server's
  public key. Go's driver requests it (`go-sql-driver/mysql` v1.9.3, `auth.go`, request
  byte `0x02`) and encrypts the password with it. Go connects to a freshly started MySQL
  8.0.46 with the Gorse DSN and no TLS, cold: `cache.Open` on
  `mysql://root:password@tcp(127.0.0.1:3306)/` returns, and `TestMySQL` passes. The port
  did not: without `mysql-rsa` sqlx fails with `RSA auth backend disabled`. The `mysql`
  feature now enables `sqlx/mysql-rsa`, which requests the key the same way (sqlx-mysql
  `connection/auth.rs`). `mysql_cold_full_authentication_connects` creates a fresh
  account, so its first login is the cold full authentication, and drops the account.
- **X-145 Pre-release RSA dependency.** `mysql-rsa` pulls `rsa` 0.10.0-rc.19, and its
  `pkcs1`, `pkcs8` and `crypto-bigint` 0.7 line, all pre-release. `rsa` 0.10.0-rc.19 is the
  newest release on the index, and sqlx 0.9.0 requires that line, so the latest-stable rule
  cannot be met on this path. Enabling it also moved `ctutils` 0.4.3 to 0.4.6 (the latest
  0.4.x) in the lock: `crypto-bigint` 0.7 needs `ctutils` 0.4.5 or newer, and the locked
  0.4.3 could not satisfy both. `libsqlite3-sys` is still one copy (0.37.0). `cargo audit`
  was not run here.

## Evidence

- Go oracle: `go test` on `storage/cache` at add21b5 passes against MySQL 8.0.46,
  PostgreSQL 10.0 and SQLite, with `MYSQL_URI` and `POSTGRES_URI` set.
- `MYSQL_URI=... POSTGRES_URI=... cargo test -p gorse-storage --features
  mysql,postgres,sqlite cache::sql`: 10 passed, 0 failed, 0 ignored. The MySQL and
  Postgres suites run against the live servers (no skips).
- `cargo clippy -p gorse-storage` with `-D warnings` is clean for: no features,
  `sqlite`, `mysql`, `postgres`, `mongodb`, `mongodb,mysql`, and all three.
- Go oracle, cold: a freshly started MySQL 8.0.46 with no logins since start, no TLS.
  `cache.Open("mysql://root:password@tcp(127.0.0.1:3306)/", "gorse_")` returns, and
  `go test ./storage/cache -run 'TestMySQL$' -count=1` passes (go1.27.0, `--- PASS:
  TestMySQL`).
- Port, cold account: `mysql_cold_full_authentication_connects` fails with `RSA auth
  backend disabled` before `sqlx/mysql-rsa` and passes after it. The live cache suites
  (`cache::`) pass: 22 passed, 0 failed, no skips.
- `cargo fmt --all --check` is clean.
- `cargo clippy --workspace --all-targets -- -D warnings` is clean.
- `RUSTDOCFLAGS='-D warnings' cargo doc --workspace --no-deps` is clean.
- `MYSQL_URI=... POSTGRES_URI=... cargo test --workspace --no-fail-fast`: 905 passed,
  0 failed, 13 ignored. The ignored tests are the dataset tests that need `cdn.gorse.io`,
  `math32_exhaustive` and `deeper_than_go_stack_limit` (release only, about 5 GB), and the
  two `godebug_child` tests, which their parent tests run. The Redis and MongoDB suites
  return early without `REDIS_URI` or `MONGO_URI`, so this gate does not exercise them.
