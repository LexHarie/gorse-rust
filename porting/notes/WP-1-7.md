# WP-1-7 notes: common/expression

Provisional ids; the integrator renumbers them into `PORTING_NOTES.md` and
`PORTING.md`. The Rust module is `crates/gorse-common/src/expression.rs`; the Go
oracle data is `crates/gorse-common/tests/data/expression_golden.json`, written by
`contracts/tools/exprgolden`.

## Plan corrections

- **C-WP17-1 `common/expression` is not expr-lang.** The project plan's risk 3
  and `porting/crate-selection.md` ("Gorse uses expr-lang only through
  `common/expression` and the recommend filters") treat this package as the
  expression evaluator. It is the feedback type expression grammar
  `<feedback_type>[<operator><value>]`, one regexp and a float compare
  (`expression.go:28`); it imports no expr-lang. expr-lang is imported by
  `config/config.go` (`parser.Parse` validates the `item_expr` fields,
  `config.go:975`), `logics/non_personalized.go`, `logics/item_to_item.go`,
  `logics/user_to_user.go` and `cmd/gorse-bench`. Risk 3 stays with WP-3-6
  (D-10). Consequence for the plan: WP-1-15 (config) needs an expr-lang
  *parser* to validate configs, which WP-1-7 does not provide; it either waits
  for that part of WP-3-6 or gets a parser-only work package first. The
  crate-selection row's wording should be corrected the same way (not edited
  here).

## Decisions

- **D-WP17-1 `regex` 1.13.1 with the Go pattern verbatim.** RE2 and the `regex`
  crate share the syntax used here, leftmost-first submatch semantics, ASCII
  classes for `[a-zA-Z0-9_]` and `$` matching only at the end of the text. The
  golden corpus (902 parse cases: every expression in the Go tests and config
  files, 75 edge cases, 400 random strings over the pattern's alphabet plus
  space, `-`, `+`, `e` and `é`, 300 random well-formed values) agrees on every
  split, every rejection and every value bit. Recorded in
  `porting/crate-selection.md`.
- **D-WP17-2 `serde` impls stand in for `MarshalJSON`/`UnmarshalJSON` inside
  larger documents**; the Go methods themselves are ported as `marshal_json`
  (byte-exact, HTML-escaped) and `unmarshal_json` (Go's errors). `serde` and
  `serde_json` move from dev-dependencies to dependencies of `gorse-common`
  (`unmarshal_json` validates with `serde_json`).
- **D-WP17-3 `ExprType` is a closed enum.** Go's `ExprType` is an `int`, so Go
  code could build other values (`String` gives `""`, `Match` gives false), but
  no input does: `FromString` maps to the five constants and `FromPB` leaves the
  field alone for unknown enum numbers (Q-WP17-6). Go `Match` is `matches`
  (`match` is a Rust keyword).

## Quirks reproduced

- **Q-WP17-1 `=` parses and matches every value.** The pattern accepts `=`, the
  switch maps it to `None` (`expression.go:84-95`): `a=5` gives type `a`,
  `None`, value 5, so `Match` ignores the value, `String` prints `a` and `ToPB`
  still sends 5. Golden `a=5`, `a=5.5`, `a=` cases.
- **Q-WP17-2 A value without an operator is parsed and then ignored.** `a.5`
  gives type `a`, `None`, value 0.5; the type takes digits greedily, so `a1.5`
  gives type `a1` and value 0.5, and `a1.` fails on the value `.`. Golden edge
  cases `a.5`, `a1.5`, `a12.34`, `a1.`.
- **Q-WP17-3 `FromString` is not atomic and keeps the old value.** The type and
  operator are written before the value is parsed; a bad value then sets the
  value to what `strconv.ParseFloat` returned (0 for `invalid syntax`, `+Inf`
  for `value out of range`) and returns the error. Text without a value leaves
  the previous value in place. Every corpus input is replayed from a zero value
  and from `{previous, Greater, 5}`.
  Combined with `encoding/json` decoding into the elements already in a slice,
  this carries a stale value across a config override (probe below:
  `["like"]` over a file value `star>=3` gives `{like, None, 3}`). Only `ToPB`'s
  value field shows it. `master.applyRecommendOverride` decodes
  `RECOMMEND_CONFIG` into `cfg.Recommend` that way; for WP-1-15/WP-4-3.
- **Q-WP17-4 Values of 1e6 and more, or below 1e-4, do not survive a round
  trip.** `String` formats the value with `%v`, which switches to exponent form
  outside `[1e-4, 1e6)` (`read>=1e+06`, `x>1e-07`), and the pattern has no
  exponent. So a config whose expression holds such a value marshals fine, but
  unmarshalling it back fails (probe below). `postConfig` stores the marshalled
  `Recommend` in the meta store and `applyRecommendOverride` reads it back on
  start (error logged, `master.go:328`) and on reload (`master.go:183`, which
  then fails); inferred from the call sites, for WP-4-3 to confirm. The Rust
  `Display` matches Go's `%v` on 858 golden values (hand-picked edges, every
  power of ten and 1.5x from 1e-30 to 1e30, 400 random bit patterns, 200 short
  decimals).
- **Q-WP17-5 `MarshalJSON` escapes `<`, `>` and `&`** (`json.Marshal` of the
  string): `"test\u003c16"`, asserted by the Go test. The serde `Serialize`
  writes the plain string; matching Go's bytes in a whole document needs a
  writer that escapes every string like Go, which every go-restful response
  also needs (for the REST work packages).
- **Q-WP17-6 `FromPB` keeps `ExprType` for an unknown enum number** (Go's
  `switch` has no default). Golden `from_pb` cases with 5, -1, 99, `MaxInt32`
  and `MinInt32`, starting from `Greater`.
- **Q-WP17-7 `MarshalJSON` has a pointer receiver.** A value that is not
  addressable (passed by value, a map value) encodes as the default struct
  `{"FeedbackType":"read","ExprType":4,"Value":3}`; slice elements and pointers
  use the string form. Every Gorse field is a slice
  (`[]expression.FeedbackTypeExpression`), so the Rust `Serialize` always writes
  the string form.
- **Q-WP17-8 JSON `null` is an error inside a slice but fine for the slice.**
  `UnmarshalJSON("null")` parses the empty string and fails; a `null` slice is
  set to nil without calling it. serde's `Vec<T>` rejects `null`, so the config
  types (WP-1-15) need `Option` or a default there.

Probe, run with `go run` from a scratch `main` package inside the module:

```
value: {"FeedbackType":"read","ExprType":4,"Value":3}
pointer: "read\u003e=3"
slice: ["read\u003e=3"]
map value: {"k":{"FeedbackType":"read","ExprType":4,"Value":3}}
override: err=<nil> [{FeedbackType:like ExprType: Value:3}] ToPB value=3
round trip: ["read\u003e=1e+06"] -> err=unmarshal FeedbackTypeExpression: invalid expression format, expected format: <feedback_type>[<operator><value>]
null slice: err=<nil> nil=true
```

## Deviations

- **X-WP17-1 `unmarshal_json` of input that is not JSON returns serde_json's
  message** (`Error::Syntax`), not Go's scanner text. Go's decoders check the
  whole document before calling `UnmarshalJSON`, so only direct calls can pass
  such input, and none in Gorse does. Valid JSON (including lone `\u`
  surrogates and invalid UTF-8, which Go turns into U+FFFD) is decoded like Go;
  golden `unmarshal_json` cases cover both.
- **X-WP17-2 serde errors carry serde_json's position suffix.** Through
  `Deserialize`, Go's text is followed by ` at line L column C`; the test checks
  the text exactly apart from that suffix. A string element with a lone
  surrogate escape or invalid UTF-8 fails in serde_json before reaching the
  visitor, with serde_json's message, where Go fails with
  `invalid expression format`; both reject it.

## For the integrator

- **prost drops `-0.0` from proto3 doubles; protobuf-go writes it.** Go
  encodes `value: -0` as `19 00..00 80`, prost compares with `0.0` and leaves
  the field out, so a Rust sender delivers +0 (probe: prost 0.14.4 encodes
  `{test, None, -0}` as `0a0474657374`). This is a `gorse-protocol` behaviour
  for every double and float field, outside this WP; `expression_to_pb_matches_go`
  asserts the exact difference on its 15 `-0` cases so a prost change is
  noticed. Harmless for this message (no parse gives `-0`, and `Match` treats
  -0 and +0 alike).
- `contracts/README.md` "Regenerating" should list
  `go run ./contracts/tools/exprgolden -out crates/gorse-common/tests/data/expression_golden.json`
  (not edited here). Regenerating gives a byte-identical file.
- New dependency: `regex` 1.13.1 (workspace). `gorse-common` now depends on
  `regex`, `serde`, `serde_json`; dev-dependency `prost` (decoding Go bytes in
  the golden test).
- Go's `%v` float formatting (`format_float_v`) and `json.Marshal` string
  escaping (`go_json_quote`) are private to this module; lift them into a shared
  module when a second caller appears (the Go-compatible JSON writer above
  needs both).
