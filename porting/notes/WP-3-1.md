## Decisions taken to keep the port faithful

- **D-WP31-4 BPR jobs share one lock.** Go's BPR epoch jobs update the factors without
  locks (racy with `Jobs > 1`). Here each job takes one lock on the factors and runs its
  update whole. With `Jobs = 1` this is Go's exact sequence. With `Jobs > 1` the result
  depends on scheduling in Go too, so it is not expected to match bit for bit.
- **D-WP31-5 ALS rows are solved from a snapshot.** Go's ALS jobs in one sweep write
  disjoint rows and read only the other side, so there is no race. Each row is solved in
  a local copy and written back when the sweep ends. This gives the same result as Go for
  any `Jobs`.
- **D-WP31-6 BPR `cost` is not computed.** Go accumulates
  `math32.Log1p(math32.Exp(-diff))` into `cost[workerId]` and never reads it. Dropping it
  changes no output, so `Log1p` is not needed by this WP.
- **D-WP31-7 Dictionaries are copied.** Go's model shares the split's `FreqDict` pointer.
  The Rust model copies it, counts included, so a later change to the split does not
  change the model. Go's `assert.Equal(trainSet.GetUserDict(), m.GetUserIndex())` holds
  for the copy.
- **D-WP31-8 Gob parameters.** `gorse_common::encoding::gob::Params` and
  `gorse_model_core::params::Params` are different types, with no conversion between them
  yet. `to_gob` and `from_gob` are private to `cf/model.rs`. If WP-3-2 needs the same
  conversion, the integrator should move it into one place (`gorse-model-core`).

## Deviations (behaviour differs from Go)

- **X-WP31-1 Log2 is a stand-in (O-3 stays open).** `math32.Log2` is
  `float32(math.Log2(float64(x)))`, and Go's `math.Log2` uses Frexp and Go's float64
  `math.Log` (assembly on amd64). Gorse has no port of that yet, so `evaluator.rs` uses
  `f64::log2`. The difference is at most an ulp of float64 and vanishes on rounding to
  float32; the replay confirms it for the values it covers. The integrator should replace
  it when O-3 closes.
- **X-WP31-2 Cancelled fits.** Go updates the factors in place, so a cancelled fit can
  leave them partly updated. Here a phase is written back only when it completes, so a
  cancellation leaves the factors as the last completed phase left them. `Fit` returns the
  zero score in both cases.
- **X-WP31-3 Failed reads.** Go's `Unmarshal` assigns the parameters and the first factor
  set before a later read fails, so it can leave a half-read model. Here a failed
  `unmarshal` leaves the model unchanged, except that the parameters may already be set.
- **X-WP31-4 Negative counts.** Go panics when a negative `NFactors` sizes a slice, and
  when a negative predictable count is passed to `make`. Here a count parameter below 0
  counts as 0, and a negative predictable count is `Error::NegativeCount`.
- **X-WP31-5 Unregistered parameter types.** Go's gob encoder fails for a `[]any` or a
  `map[string]any` parameter with `gob: type not registered for interface`. The Rust error
  has the same text (`Error::UnregisteredType`).
- **X-WP31-6 Evaluate takes `&mut` test set.** Go's `SampleUserNegatives` caches on the
  split, so Rust takes `&mut dyn CfSplit` and clones the cached negatives for the call.
  The results are the same.
- **X-WP31-7 Type split.** Go's `Model` interface is `cf::Model` here, and
  `MatrixFactorization` is a separate trait with the prediction methods. `GetModelName`'s
  type switch is the `model_name` method.

## Evidence

- Golden check: `conformance/tests/cf_golden.rs` (`cf_oracle_matches_golden`) runs the
  generator with `-epochs 5` into a temporary directory and requires `train.tsv`,
  `test.tsv` and `golden.json` to equal the committed copies. It fails with the reason
  when Go is not on PATH. The golden was regenerated by hand before this court ruling.
- Generator: `go run ./contracts/tools/modelreplay -mode cf -out crates/gorse-model/testdata/cf -epochs 5`
  (Go, add21b5, one job, `RandomState` 0, `Verbose` 1, default `Candidates` and `TopK`).
  Output: `train.tsv`, `test.tsv` and `golden.json`, 39 KB in total.
- Replay: `cargo test -p gorse-model cf::replay -- --nocapture` compares 815 values per
  model (5 epochs x 3 metrics, plus 40 x 8 user and 60 x 8 item factor entries). The
  largest difference is 0 for BPR and ALS, against a tolerance of 1e-5.
- Mutation check: changing BPR's learning rate from 0.05 to 0.051 makes the replay fail
  with a difference of 8.93e-4, so the gate is sensitive to the model.
