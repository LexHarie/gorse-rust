# WP-3-5 notes: item-to-item and user-to-user logics

Provisional ids (`D-WP35-n`, `Q-WP35-n`, `X-WP35-n`, `O-WP35-n`) for the integrator to renumber.

Ports: `logics/item_to_item.go` and `logics/user_to_user.go` @ add21b5.
Rust: `crates/gorse-logics/src/item_to_item.rs` (tests in `item_to_item/tests.rs`) and
`crates/gorse-logics/src/user_to_user.rs` (tests in `user_to_user/tests.rs`).
Oracle: `contracts/tools/item2itemgolden` and `conformance/tests/item_to_item_oracle.rs`.

## Design

- **D-WP35-1 Enums over four concrete recommenders.** Go's `ItemToItem` and `UserToUser`
  interfaces become the enums `ItemToItem` and `UserToUser`. Each variant wraps one public
  struct for a Go type (`EmbeddingItemToItem`, `TagsItemToItem`, `UsersItemToItem`,
  `AutoItemToItem`; `EmbeddingUserToUser`, `TagsUserToUser`, `ItemsUserToUser`,
  `AutoUserToUser`). Go's unexported constructors (`newEmbeddingItemToItem` and the rest)
  are folded into `new_item_to_item` and `new_user_to_user`, which dispatch on the configured
  type and read the IDF from the options (Go passes it as an argument). Go's interface has a
  closed set of four implementations, so an enum needs no trait object or boxed future.
- **D-WP35-2 `add` takes the processed item.** Go's master passes `dataset.GetItems()` to
  `Add` (`master/tasks.go` 816-818) and `dataset.GetUsers()` (865-867). The dataset's
  `AddItem` and `AddUser` run `processLabels` on the labels (`dataset/dataset.go` 198-225,
  at 201 and 219), so Go's `Add` sees processed labels. The port's `add` takes
  `DatasetItem` and `DatasetUser` for the same reason. The non-personalised path reads raw
  storage items (WP-3-6 is right to do so, as D-225 records).
- **D-WP35-3 The expression sees Go's types.** The `item` variable is a `Value::Struct` of
  Go's `data.Item` (`item_type`), and `user` one of `data.User`. A processed label becomes
  the Go value it is in Go: `dataset.ID` is a named `int32` (`id_type`), `[]dataset.ID` a
  slice of it, FP16 bits a `[]uint16`, and a map a `map[string]any` (`processed_value`).
  `data.Item` has an `UpdateAt` field (`storage/data/database.go` 83) that `AddItem` does not
  copy (`dataset/dataset.go` 213-225), so the port's `UpdateAt` is the zero time.
- **D-WP35-4 Go's type switches are exact.** `flatten` (`logics/item_to_item.go`, around
  250-260) matches `dataset.ID`, `[]dataset.ID` and `map[string]any` by exact type, and the
  port does the same. `floats.FromAny` and Go's `anyToFloat32` match exact types too: a named
  type such as `dataset.ID` does not convert, and `[]uint16` is taken as it is.

## Quirks reproduced

- **Q-WP35-1 Tags come only from processed labels.** `flatten` has no case for a string, a
  `[]string` or a `[]any`, so a raw label gives no tags. The port reproduces this, and a tags
  or auto recommender over raw labels writes an empty tag set.
- **Q-WP35-2 Expression failures are logged, not returned.** In Go, the item embedding
  recommender logs `failed to evaluate column expression` (`logics/item_to_item.go` 157) and
  `failed to convert column to FP16 slice` (162), then returns nil (`Add`, 140-143, also
  returns nil for an empty vector). The item tags recommender logs
  `failed to evaluate column expression` (185) and returns nil. The user embedding
  recommender logs `failed to evaluate column expression` (`logics/user_to_user.go` 144) and
  `invalid embedding column type` (149, for a conversion failure or an empty vector), and
  returns nil. The user tags recommender logs `failed to evaluate column expression` (176)
  and returns nil. The port logs the same messages with `tracing::error!` and returns `Ok`.
- **Q-WP35-3 Errors come in Go's order.** `new_item_to_item` checks the vector store, then the
  IDF of the type (tags, users, auto), then the column of the users type, which is the only
  column error (`column is not supported in users item-to-item`, `logics/item_to_item.go`
  207). `new_user_to_user` checks the store, then the IDF, then the column of the items type
  (`column is not supported in items user-to-user`, `logics/user_to_user.go` 196). The messages
  are Go's `errors.New` texts.
- **Q-WP35-4 A query drops the row's own ID and a non-positive dot score.** `QueryItemToItem`
  does it at `logics/item_to_item.go` 73-74, and `QueryUserToUser` at `logics/user_to_user.go`
  73-74.
- **Q-WP35-5 Scores depend on the type.** The `auto` type halves the store's score
  (`item_to_item.go` 67-69), and an `embedding` score is `1 / (1 - s)` on the Euclidean
  distance (76-78). `user_to_user.go` has the same scaling (67-78).

## Deviations

- **X-WP35-1 Go sorts the feedback slice in place.** `usersItemToItem.Add` and
  `autoItemToItem.Add` call `slices.Sort(feedback)` (`item_to_item.go` 213, 236-237), and so do
  `itemsUserToUser.Add` and `autoUserToUser.Add` (`user_to_user.go` 205, 231). That reorders
  the caller's `dataset.GetItemFeedback()[i]`. The port takes `&[i32]` and does not reorder.
  The vector does not depend on the order: Go's pruner (`logics/vector_writer.go` 243-275)
  keeps the top `maxSparseVectorNNZ` entries (1024, line 36) by value, breaks ties toward the
  smaller index, and skips an index it has already seen. The Rust pruner
  (`crates/gorse-logics/src/vector_writer.rs` 100-112) uses the same rule. The only reads of the
  feedback slices in `master/tasks.go` are at 197-204 (before the update) and at 818 and 867
  (the calls themselves), so no later code sees the sorted order.
- **X-WP35-2 The tests pass processed labels.** Go's tests pass raw labels, such as a bare
  `[]float32` (`logics/item_to_item_test.go` 109) or `map[string]any{"embedding": []float32{...}}`
  (from line 128). The Rust tests pass what the dataset gives for them: `[]float32` as FP16
  bits (Go's `floats.FromAny` produces the same bits, so the stored vectors are the same),
  tag IDs as `dataset.ID` values, and the raw string `"hello"` as a plain label. The
  "Column does not exist" case passes a bare float list as the labels, as Go does at line 109.
  The Go suite methods keep their assertions.
- **X-WP35-3 An empty result is an empty `Vec`, not `nil`.** Go's `QueryItemToItem` returns
  `nil` when the query row has no vector (`logics/item_to_item.go` 56-58), and an empty
  non-nil slice when the row has no neighbours. The port returns an empty `Vec` in both cases.
  Go's callers reassign or filter the result before writing a response (`server/rest.go`
  860-872 and 906, `server/rest.go` 1130, `master/rest.go` 1129-1135 and 1177-1186, which sets
  `nil` itself). The REST work must confirm that both encode the same way. This is not
  checked here.
- **X-WP35-4 `n` is `usize`.** Go's `n` is an `int`. A negative `n` makes Go's
  `make` in `QueryItemToItem` (`item_to_item.go` 71) panic at runtime. The port cannot take a
  negative count.
- **X-WP35-5 `IDF[T]` is not ported.** `logics/item_to_item.go` 247 declares a generic
  `IDF` type that nothing else in Go uses. It has no behaviour to port.
- **X-WP35-6 `labels_value` is copied.** `item_to_item.rs`, `non_personalized.rs` and
  `reranker.rs` each have a private `labels_value`. They are not textually identical. They are
  kept apart because `non_personalized.rs` and `reranker.rs` are outside this WP, so the
  integrator should check all three against D-228 (Q-255).
- **X-WP35-7 Neighbours come from an exact store.** Go's `xvec` answers with HNSW, which is
  approximate (O-30). The port's store scans exactly (X-75). Neighbour order at score ties and
  the last bit of a score can therefore differ. The oracle compares around both (below).

## Open

- **O-WP35-1 Q-254 is closed.** D-232 closes Q-254 on integration `1c4505a`. This branch merges
  that head, so the recommenders hold `Arc` payloads and are `Send + Sync`. A test in `item_to_item/tests.rs` and `user_to_user/tests.rs` (`recommender_is_send_and_sync`)
  checks it when the tests compile.
- **O-WP35-2 `json.Number` labels become floats.** `labels_value` maps `Labels::Number` to a
  float, as D-228 rules for WP-3-6 (Q-255).
- **O-WP35-3 The master must pass processed items.** The Rust master's item and user update
  tasks must build `DatasetItem` and `DatasetUser` from the processed dataset, not from storage
  items. That master code is not in this WP.

## Tests and evidence

- Seven item-to-item tests (`column_func`, `embedding`, `clean`, `hidden`, `tags`, `users`,
  `auto`) mirror the seven `Test*` methods of `ItemToItemTestSuite`
  (`logics/item_to_item_test.go`). Five user-to-user tests (`embedding`, `clean`, `tags`,
  `items`, `auto`) mirror the five of `UserToUserTestSuite`. Each recommender also has a `recommender_is_send_and_sync` test (Q-254, D-232). None is ignored:
  all run offline.
- `conformance/tests/item_to_item_oracle.rs` runs `contracts/tools/item2itemgolden` with
  `go run`. The tool sets `casesPerKind = 5` and `rowsPerCase = 30` over eight kinds (four
  item and four user types), 40 seeded cases in all, and the test asserts 40. Stored vectors
  match bit for bit. Each row's neighbours match as a set. Their scores agree within 1e-6 of
  `max(|score|, 1)`. Only the neighbours tied at the lowest score may differ (X-75 and O-30).
  The mutation check changed the `auto` score scale from 0.5 to 1.0, and the oracle failed.
- `conformance/Cargo.toml` gains `gorse-dataset` as a dev-dependency for the oracle.
